# EPUB 怎么显示

2026-11-24。比较两条路：**A** 保留原书 XHTML，套上 Loci 的样式，用 WebKit 显示；**B** 转成 Markdown，用现有的正文阅读器显示。验证代码（WebKit 渲染脚本和 Markdown 一侧的快照测试）在 `spike/epub` 分支上，不合并。

## 样本

| 书 | 来源 | 测什么 |
|---|---|---|
| 鲁迅《吶喊》·《孔乙己》 | 维基文库导出的 EPUB 3 | 中文正文、专名号（人名地名下的横线）、书里自带的导航表 |
| 《吶喊》 | Project Gutenberg #27166 | 从 TXT 转出的 EPUB |
| Pro Git 第 3 章 | GitHub release 2.1.450 | 代码块、行内代码、配图、交叉引用 |
| Marcus Aurelius《Meditations》卷四 | Standard Ebooks | 英文长段落、小型大写标题、尾注编号 |

B 用 Pandoc（`-t gfm-raw_html`）转换，相当于手写转换器能做到的上限。

## 结论

**选 A。** 前期做一个单纯的读书页面，A 的效果更像一本书，代价也更小。

| | A. WebKit + 原书 + Loci 样式 | B. Markdown + 现有阅读器 |
|---|---|---|
| 中文专名号、楷体引文、居中、右对齐 | 保留 | 丢失：Markdown 没有对应写法 |
| 中文首行缩进 | 一条 CSS | 现有阅读器没有，要新加 |
| 左右翻页、双栏 | CSS 分栏就能做到 | 要自己做 TextKit 分页 |
| 章节标题 | 保留 | 标题写在表格或 `div` 里时会丢（《孔乙己》的标题就丢了） |
| 尾注编号 | 上标，可以点 | 变成一个普通链接 |
| 代码块、配图 | 都正常 | 都正常 |
| 划线、选段提问、双语 | 要在 WebKit 里重做 | 现成可用 |

## A 必须做到的

- **主题要压过书里的样式。** 书自带的内联样式（比如维基文库导航表的白色背景）在暗色下会让文字看不清。只覆盖 `p`、`td` 这些选择器不够，要对 `body *` 统一去掉背景、文字颜色继承正文，只给 `pre` 单独设底色。改完以后两种主题都能正常显示。
- **字体用 `ui-serif`。** 写 `"New York"` 这个名字 WebKit 找不到，会回落到宋体自带的西文字形。
- **英文两栏两端对齐时字间距太松。** 每栏大约 50 个字母，就算开了 `hyphens: auto` 间距还是很大。英文改成左对齐或者把栏加宽，正式做的时候再调。
- **透明底的配图在暗色下看不清。** Pro Git 图里的提交编号是深色字，背后是透明的。配图要垫一层纸色。这个问题 B 也一样有。
- **结构太差的书两条路都救不了。** 古腾堡版《吶喊》每一个硬换行都是一个 `<p>`，书里也没有标题，A 和 B 显示出来都是断行。这种书要在导入时识别出来，按 TXT 的方式重新分段。

## 整本书怎么翻

2026-11-24 补验。代码在 `spike/epub` 分支的 `spike/epub/pager/`：自己写的 ZIP 读取（中央目录 + Foundation 的 raw deflate 解压），WebKit 自定义协议从 `.epub` 里直接取章节、图片和样式，一章一个页面，CSS 分栏翻页。四本样书加一本生成的大书（500 章、150 张图、15 MB）都从头翻到尾。

| | 结果 |
|---|---|
| 打开一本书（读中央目录、`container.xml`、OPF） | 1–6 ms，500 章的书也一样 |
| 载入一章并排好版（本机） | 中位 5–50 ms，最慢 300 ms（第一章，WebKit 冷启动） |
| 章内翻一页 | 0.1 ms：只是把 `body` 平移一屏宽 |
| 每次请求加 600 ms（中继的实测延迟） | 一章 1.3 s，带图的章最慢 2.4 s：先取章节，再并行取样式和图，两轮往返 |
| 改窗口大小或字号后找回原句 | 四种尺寸 × 三本书全部找回，原来那页的第一个字仍在当前页上，用时 15–50 ms |

**怎么定位**：「这一页从哪开始」是正文里第一个露出来的字：对文本节点按位置二分，再在节点里按字二分，记成从 `body` 起的子节点下标路径加字符偏移。还原时取那个字的矩形，算出它在第几屏。路径对同一个文件是稳定的，因为书不会变。

**分栏要这样写**：`body` 固定高、`column-gap` 等于左右边距的两倍，一屏正好是两栏（或一栏）加边距，翻页平移整屏宽。用 `scrollLeft` 翻到最后一屏会被浏览器夹住，错开半个边距；改用 `transform` 平移。算总页数时要先去掉平移再量 `scrollWidth`。

**踩到的坑**：

- 维基文库的图写着 `loading="lazy"`，在分栏里不在视口内的图永远不载入，等图的那一步会卡死。注入脚本时把所有图改成 `eager`，等图最多等几秒。
- 有的书 XHTML 不合法，WebKit 按 XML 解析会显示一个报错页面，只渲染到出错的地方。要能识别出来（页面里有 `parsererror`），改按 HTML 再载一次。
- 远程时，翻到下一章要等两轮往返。读这一章时就把下一章和它引用的文件先取到界面这边，翻过去就和本机一样快。

## 没有验证的

- WebKit 里的划线和定位：怎么用 JS 取选区，怎么映射到定位符。
- 竖排和固定版式的书。
- 结构太差、要按 TXT 重排的书怎么自动认出来。
