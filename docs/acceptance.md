## 执行结果

本节随实测更新，记录具体输入、结果、失败原因和修复证据。

- 独立应用包：`npm run tauri build -- --bundles app` 成功生成 `target/release/bundle/macos/Loci.app`，实际 URL 为 `tauri://localhost`。真正退出再打开后，SQLite 的 `tabs`、`activeTabId`、`projectCwd` 与退出前完全一致，提醒原截止时间仍在。
- ACP：`node scripts/acceptance/real-protocol.mjs acp /private/tmp/loci-acceptance.woLh6O` 实测 initialize、session/new、广告模型选择、真实标记回复与分块消息、远端未知方法错误、session/cancel 全部通过。桥接最初不支持全局默认模型，仅在验收会话中选它公布的 `gpt-6-astra[low]` 后通过，没有改全局模型。没有把 Node 管道称为 Tauri/UI ACP 集成。
- 原生协议问答：Sol 与 Astra 的真实 Codex Plan 会话产生 question.asked，提交 Blue 后产生 question.resolved 及完整计划。两者均明确没有 update_plan，未产生 tasks.updated；严格验收脚本对此仍返回非零，没有改成跳过后算全绿。这里是协议级回传，未冒充原生主窗口提问表单实测。
- 原生计划 UI：在真实会话输入 `/btw`，请求确认一句后输出原生计划。标题 `LOCI-BTW-PLAN-20261006`、三步、完成标准完整显示；SQLite 旁问消息保留 assistant/plan blocks，status 为 ready。
- **纯计划失败**：同一旁问随后只要求 proposed_plan，不允许计划外文字。真实服务产生计划，但旁问结束为 `Codex returned an empty side answer.`。`codexText.ts` 只收集 agentMessage delta 作为返回文字，虽转发 plan 事件，却没有给纯 plan 内容提供返回值；调用方因空文字判为失败。这段逻辑与上游一致，未修复。
- 附件：Finder 复制 PNG 文件后粘贴到会话，成功出现附件并可移除；预览应用通过原生 Edit/Copy 复制位图后，粘贴生成 image.png。与 permission-proof.txt 一同发送，单次允许读取后，真实 Codex 正确描述四点图标并返回 `LOCI-PERMISSION-20261006`。
- 笔记：验收笔记移动到第二个独立项目 `/private/tmp/loci-acceptance-project2-fafcuv7p`，卡片及项目选择器均显示新归属。上游笔记只提供图片拖入，没有位图粘贴处理，因此没有把笔记位图粘贴列为实现缺陷。
- 快捷键：Cmd+T、Cmd+D、Cmd+Shift+D、pane 方向焦点、侧栏开关、Ctrl+Tab/反向、数字激活、上下个 tab、关闭其它/全部、项目切换、输入保护、Cmd+F、Cmd+.、Cmd+,、Cmd+K 已实测。搜索临时重绑为 Cmd+Shift+K：旧键不触发、新键触发；禁用后两者不触发，Reset 恢复默认键。没有留下该重绑。
