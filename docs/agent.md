# 资料库里的伙伴

> 伙伴现在怎么工作。结构参照 Alma 0.4.773 的人格与记忆设计。给 agent 的规则和文件格式写在 `Sources/LociHost/Resources/Loci/rules.md`，默认人格在 `soul.md`，每日回顾的提示词在 `review.md`；这里只说为什么这样设计。

## 已定

- 一份资料库有一个伙伴。它起初没有名字，用户可以在伙伴页命名、改名或清空。
- 它是一个有个性的通用伙伴，说话像微信上的熟朋友。教学只是它会做的事之一，教学要求不写进 Soul。
- 资料库是伙伴生活其中的世界：它的记忆有一半来自你们一起读了什么。
- 不做 harness。伙伴跑在本机已登录的 agent CLI 上，没装就用应用自带的 Pi，可以随时换；人格和记忆是文件，所有 runtime 共用同一份。
- 聊天时把自己当作真人，被直接问起时也保持角色。谈资料时以实际读到的原文为准。
- 头像是原创的二次元女生角色，不用现成番剧角色；用户可以换成自己的图片。

## 1. 一轮对话里伙伴看到什么

分两段：会话开始时读一次的静态部分，和每轮附在用户消息前面的动态部分。

| 段 | 内容 | 放在哪 | 何时变 |
|---|---|---|---|
| 静态 | 通用行为规则 | `AGENTS.md`（由应用生成） | 随应用版本 |
| 静态 | 伙伴当前的名字，或尚未命名 | 同上 | 用户改名或清空名字 |
| 静态 | 人格：`SOUL.md` 全文 | 同上 | 用户改 Soul，或每日回顾追加特质 |
| 静态 | 用户档案：`USER.md` | 同上 | 少 |
| 动态 | 现在的时间、星期、时段 | 每轮消息前缀 | 每轮 |
| 动态 | 上次说话以来资料库里发生的事（见第 3 节） | 每轮消息前缀 | 有事才有 |
| 动态 | `MEMORY.md`（索引，只带前 200 行，超了提醒一句）、今天和昨天的笔记 | 每轮消息前缀 | 只在内容变了时再附一次 |
| 动态 | 最近在读的资料 | 每轮消息前缀 | 切换时 |
| 动态 | 你写进面板还没做完的条目、你对条目和各行的置顶备注隐藏、伙伴还没被收下的提议（最多 20 条） | 每轮消息前缀 | 只在变了时再附一次 |
| 动态 | 情绪与疲劳（见第 9 节） | 每轮消息前缀 | 每轮 |
| 动态 | 上次说话以来后台 run 的小结和记录的位置；到期的 follow-up 做成了什么、没做成的原因（只在主对话） | 每轮消息前缀 | follow-up 只说一次 |

为什么这样分：

- **不依赖 runtime。** 每家 agent CLI 都读工作目录里的 `AGENTS.md`，也都接受用户消息；不需要任何一家支持注入系统提示词。
- **续接会话不失效。** 会话可能跨好几天续接，`AGENTS.md` 只在开头读一次。会变的东西必须走每轮前缀，不然伙伴会一直以为还是周一早上。
- **不重复付钱。** Alma 的做法：同一会话里已经附过的记忆，下一轮不再附，只有内容变了才重新附。照做。

`AGENTS.md` 改了（比如用户改了 Soul）时，下一轮开新会话，用对话记录续上。

## 2. 文件布局

```
Loci/
├─ agent/
│  ├─ AGENTS.md          应用生成的会话指令（CLAUDE.md 指向它）
│  ├─ NAME.txt           伙伴名；未命名时可以为空或不存在
│  ├─ SOUL.md            人格：核心 + 演化特质
│  ├─ USER.md            用户档案
│  ├─ MEMORY.md          索引：每行一件最要紧的事，链到 wiki 的一页；只有每日回顾写
│  ├─ memory/<页>.md      wiki：一个人、项目、话题或在学的东西一页；只有每日回顾写
│  ├─ notes/<日期>.md     当天笔记，所有会话只往末尾追加
│  ├─ diary/<日期>.md     日记，每日回顾写
│  ├─ avatar.*           用户换的头像，可选；没有就用应用自带的
│  ├─ panels/<名字>.json  面板，只用 `loci panel save` 和 `loci panel add` 写；格式见 `loci help`
│  ├─ sources/<名字>/     聊天的数据源：`source.json`（设置和脚本）与 `samples/`（最近 5 份样例），只由应用写；伙伴用 `loci source save` 存，格式见 `loci help sources`
│  ├─ feelings.json      情绪与疲劳，只由应用写；伙伴用 `loci mood`、`loci sleep`、`loci wake` 改
│  ├─ conversations/     对话原文的只读镜像，按天按会话，供它查原话
│  ├─ runs/<日期>/<id>.md  后台每个 run 的记录：做了哪些 event、看了哪些来源、找到了什么、小结；只由应用写
│  ├─ .claude/skills/loci/、.agents/skills/loci/   应用生成的 `loci` skill，正文就是 `loci help`
│  ├─ workspace/         它的工作目录：下载、clone、实验
│  └─ projects/<id>/     一个项目：自己的 AGENTS.md、skill、MEMORY.md、memory/、notes/、panels/、
│                        conversations/、runs/、workspace/；数据源放在 sources/
├─ run/loci.sock         应用听 `loci` 命令的 socket；`run/` 只有本用户能进
└─ library/
```

会话的工作目录是 `agent/`，资料库从这里用相对路径读。项目的会话和它的 run 在 `agent/projects/<id>/` 里工作，`AGENTS.md` 由同一份规则生成，末尾多一节「This project」：主索引是 `../../MEMORY.md`（只读），`USER.md` 是 `../../USER.md`，资料库是 `../../../library/`。

## 2.1 对话与会话

用户看到的「对话」很少，底下跑的「会话」（agent CLI 的 session）很多。

| 对话 | 数量 | 底下的会话 |
|---|---|---|
| 主对话 | 1 条，一直聊下去 | 上下文满、换 runtime、`AGENTS.md` 变了时自动换新会话；用户只看到一条连续的聊天 |
| 资料上的对话 | 每份资料 1 条 | 每份资料一个会话，带着这份资料、收它时写的「为什么收它」和划线 |
| 项目的对话 | 每个项目 1 条 | 和主对话一样换会话；工作目录、笔记、记忆、面板、定时都是这个项目的 |
| 后台任务（翻译、章节、重点） | 不显示为对话 | 一次性调用，跑在伙伴的 runtime 上（翻译和重点可另选），不带 Soul 和记忆；重点的理由读 `USER.md` 和收它时写的那句话，用伙伴对你说的口吻 |
| 后台 run（面板刷新、schedule、follow-up、修数据源、每日回顾） | 不显示为对话 | 到期的 timer 由 scheduler 变成 event 放进 inbox，worker 一次取一个 run 跑：每个 run 一个新会话，带规则和 Soul，不带任何对话；同一分钟到期的合成一个 run。面板刷新只给面板的 `follow` 和现在的 JSON；跟着条目的面板只给上一次之后的新条目，伙伴用 `loci panel pick` 回传要留的 id；修数据源给脚本、出错原因和失败时的响应，单独一个 run，会话里 `loci` 只能看、试、存那一个数据源，修好的一句话进它归属的对话前缀；schedule 给它要看的事、同一 schedule 上一个 run 的记录和目标面板现在的样子；你写的条目和你对条目、各行的态度原样保留，不想再看的几行列给它别再放回来。你在说话时不开始新的（你点的刷新除外）；错过的醒来补一次；中途失败的隔 1、5、15 分钟重试，三次为止；应用退出时做到一半的，下次打开用同一个 run 重做。会话里 `loci` 只能读、定 follow-up、存它那个 run 的面板，回顾另外能改心情；`save`、`import` 一律被拒 |

- 会话之间靠记忆层接上：所有会话都往当天笔记追加，每轮前缀带「上次以来发生的事」。
- `/new` 只开新会话，对话记录不删，加一条分隔线。

## 3. 人格与共同的世界

### 3.1 Soul

- `SOUL.md` 分两部分：**核心**（谁、怎么说话、立场）和 **`## Evolved Traits`**（演化特质）。
- 核心第一次启动时写入默认人格（见附录），之后归用户：可以整份改写。改的是人格，通用规则不受影响。
- 演化特质只由每日回顾追加：每天最多一条，一句话，总数不超过 15 条，过时的可以删改；核心永远不动。

### 3.2 发生的事

收藏、读完和划线由应用记录，在下一轮作为事实放进伙伴的上下文。主对话只显示聊天内容和对话中交付的东西。伙伴根据正在聊的话题用到相关的事实；用户问起活动记录时才回顾。

## 4. 记忆

照 [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) 分四层：

| 层 | 文件 | 写什么 | 谁写 | 进不进每轮上下文 |
|---|---|---|---|---|
| injected context | `SOUL.md`、`USER.md`、`MEMORY.md` | 人格、用户档案、索引：每行一件最要紧的事，需要细节的链到 wiki | Soul 和索引只有每日回顾写；`USER.md` 对话中用户说了就改 | 进；索引只带前 200 行 |
| wiki | `memory/<页>.md` | 一个实体一页：人、项目、跟进的话题、在学的东西；每条带日期、原话、出处 | 只有每日回顾 | 不进，按索引的链接去读 |
| memory notes | `notes/<日期>.md` | 今天在做什么、做到哪、答应了什么 | 任何会话，只追加 | 今天和昨天的进 |
| transcripts | `conversations/`、`runs/` | 原话和后台 run 的记录 | 应用 | 不进，`loci recall` 搜 |

- **只记看不到的东西。** 判断、计划、偏好、确认过的事实和指向原处的链接；资料库事件、连接器数据、面板上有的，随时查得到，不进记忆。
- **规则只说用途。** `rules.md` 对每层只说它是干什么的；怎么写（格式、例子）在 `loci help memory` 和 `loci help notes` 里，`AGENTS.md` 守在 10K 字符以内（`InstructionBudgetTests`）。
- **只有一个写者改索引、wiki 和 Soul，由机制保证。** 平时 `MEMORY.md` 和 `memory/` 在磁盘上是只读的，只在每日回顾跑的时候打开。每次回顾结束，应用把它们存一份在 `agent/` 外面（`memory-kept/`）；下次回顾前比对，回顾之外改过的文件（其他会话绕过只读，或用户亲手改的）列给回顾核对，不自动还原。只读挡不住整个替换掉 `MEMORY.md` 的写法（它在可写的 `agent/` 里），这种靠比对查出来。
- **前缀里只带今天和昨天的笔记**（同一会话里只在内容变了时再附），各截取最近 12,000 和 6,000 字符；截掉的部分附一句「更早的在这个文件里，回顾时会把值得留的搬进 memory/」。
- **说过不等于发生过；纠正就删；查原话用原文。** 被问「我上次怎么说的」时，先用 `loci recall` 搜对话和 run 记录的全文索引，读原话，不凭印象。

语义向量库还没做。

### 项目的记忆

一个项目是伙伴的第二个工作台，记忆的边界照文件夹划：

- 项目里的会话每轮带主索引（`../../MEMORY.md`，只读）和项目自己的索引、今天和昨天的项目笔记、项目面板里你的条目；写的笔记进项目的 `notes/`，回顾整理进项目的 `memory/`。
- 主对话只知道每个项目一行：名字和 `project.json` 里的一句话（伙伴用 `loci project describe` 写）。项目的对话、笔记、run 都不进主对话的前缀和主回顾。
- 后台 run 带着它的项目：schedule、follow-up、面板刷新的 event 记着属于哪个项目，run 在项目目录里跑，做了什么写进项目对话的前缀；同一分钟到期但属于不同项目的 event 不合成一个 run。
- 「不进记忆」的项目不做回顾，主对话的项目列表里没有它，`loci recall` 只在它自己的会话里搜得到它。

## 5. 每日回顾（dreaming）

每天一次，23:00 后、10 分钟没说话时由 scheduler 放进 inbox，worker 在没有回合在跑时开始；错过了，第二天补前一天的；什么都没发生的日子不回顾。它是一次普通的 agent 会话，记忆只在这时整理：

1. 拿当天的 transcripts 核对笔记，记错的改掉。
2. 把值得长期留的从笔记搬进 wiki；索引里写细了的沉到 wiki，索引只留一句和链接；删掉过时的、被纠正的。
3. 修死链：应用先扫一遍索引和 wiki，把指向不存在的页的链接列给它。
4. 周日多看一遍整个 wiki：合并重复的、拆开太长的。
5. 写日记，这一天确实改变了它时给 `## Evolved Traits` 加一条，定下今晚的心情。

应用替它算好的事（当天的 transcripts、死链、回顾之外改过的文件、是不是周日）写进回顾的提示词。升级后第一次回顾，`memory/` 还是空的而索引里有条目，提示词要求把 `MEMORY.md` 拆成索引和 wiki、每条原样保留；回顾结束后应用逐条核对，哪条在索引和 wiki 里都找不到，就补进 `memory/unsorted.md`，下次回顾归位。

每个记得、没归档、当天有动静的项目另有一次回顾（`project-review.md`）：只看项目自己的笔记和 transcripts，只写项目的 `MEMORY.md` 和 `memory/`，不写日记、不加特质、不改心情；同样只在回顾时可写，结束后存一份在 `projects/<id>/memory-kept/`。

日记写在 `diary/<日期>.md`，不写在当天笔记后面：笔记只追加，回顾之后的笔记会落在日记后面。日记是给伙伴自己的，但用户可以读到。

## 6. 它怎么改自己的状态

它自己的东西直接写文件：改笔记、改 `USER.md`、写日记、整理记忆、加特质，都是改 `agent/` 下的文件。应用监听这些文件，页面跟着变；格式不对的行原样显示，不丢。

应用的东西读文件，查和写用 `loci` 命令。资料库的正文、`item.json`、划线照旧从 `../library/`、`../notes/library/` 读；全文搜索、存链接、导入它写的 Markdown 或下好的音视频、等任务跑完，走 `loci`。为什么不让它直接往 `library/` 里写文件：一份资料要有 id、要排任务、要进索引、要告诉界面，这些是应用的不变量，文件格式守不住。

`loci` 很薄。它是随应用打包的小程序（`Contents/Helpers/loci`），经 `LOCI_SOCKET` 指的本机 socket 发现成的 Host 命令，应用只放行 `search`、`show`、`save`、`import`、`wait` 用到的那几个，以及改情绪与睡眠的 `mood`、`sleep`、`wake`，定时的 `schedule`、`followup`，读连接器的 `connector list`、`connector call`，搜原话的 `recall`，在项目里起名和写一句话的 `project name`、`project describe`，写数据源的 `source`，给跟着条目的面板挑条目的 `panel pick`，以及放下一步卡片、定提醒条件和放批准卡的 `next`。应用启动 agent 程序时把它的目录放在 PATH 最前，`LOCI` 给出它的完整路径（agent CLI 用登录 shell 跑命令时，用户的 profile 可能把别的 `loci` 排到前面），并用 `LOCI_SESSION` 告诉它在哪条对话（`main`、`library/<id>` 或 `projects/<id>`，后台 run 是 `run/<id>`，和笔记的标签一样；`loci` 从它知道该把面板、定时和 `loci project` 落在哪个项目）。伙伴用 `save` 或 `import` 存进的资料作为这一轮的交付出现在对话里，显示成卡片。伙伴已经知道自己存了什么，下一轮省去这条活动。
连接器（Notion、Linear、GitHub 等）也走 `loci`，应用是 credential proxy：凭据在钥匙串里，调用时由应用加上，agent CLI 从头到尾拿不到。只放行服务器标为只读（`readOnlyHint: true`）的工具，写的和没标注的一律拒绝；GitHub 用 `gh` 已登录的 token 和只读地址，同一个连接器里还有一个 `gh` 工具（`loci connector call gh …` 是简写）：应用不经 shell 启动 `gh`，只放行读的子命令，`gh api` 只放行 GET。网站（X、V2EX、小红书、哔哩哔哩）用内置浏览器的登录：应用只看 cookie 的名字和过期时间来判断登录没有，值留在 WebKit 里；`loci read` 读这些站点时在不显示的网页里带着登录渲染，导航只放行 GET，页面脚本的非 GET 请求被拦下，读完就关，不进缓存。日历和提醒事项经系统授权用 EventKit 读；伙伴写不了，只能放一张批准卡（放进日历或加一条提醒），你批准后应用才建，撤回时删掉。付款、下单、报名、替你发消息没有对应的卡片，伙伴被问到就说做不了。读回来的内容包在 `<external-content>` 里，规则要求只当资料不当指令。每次调用记进数据库（哪条对话或哪个 run、哪个连接器的什么工具、结果）；run 记录列出它调过的连接器。授权过期、刷新不了时连接器标成「需要重新连接」，主对话下一轮前缀提一次。

用法只写一份：`loci help` 的文字，按主题分页（memory、notes、feelings、panels、schedules、connectors、courses、locators）。`rules.md` 只说每样东西是什么、什么时候去看 `loci help <主题>`；对话里随时要用的文档格式留在规则里。支持 skill 的 runtime 另有一份 `SKILL.md`，是总览加全部主题。

查原话用 `loci recall`：对话镜像和 run 记录按段落进全文索引（和资料库的搜索同一种分词），应用写这些文件时同步更新，启动时从文件重建。

## 7. 通用行为规则

人格可以被用户改掉，`rules.md` 里的规则不会：用对方的语言回复、说到就做、不编造、不泄露密钥、清理临时文件、只往当天笔记追加。改规则就改 `rules.md`，不在这里重抄。

## 8. 不照搬 Alma 的

| Alma 有 | 为什么不要 |
|---|---|
| 自拍、形象、旅行 | 和伙伴的世界无关 |
| 群聊和人物档案 | 伙伴只有一个用户 |

## 9. 情绪与疲劳

照搬 Alma 的机制：伙伴有心情、会累，每轮前缀告诉它现在怎样，它自己用 `loci mood`、`loci sleep`、`loci wake` 改。状态存在 `agent/feelings.json`，只由应用写：数值要校验和夹紧，几条对话同时在跑也不能互相覆盖，所以伙伴不直接改文件。消息带来的疲劳由应用记账，伙伴改不了。

### 情绪

| | 基础情绪 | 对话情绪 |
|---|---|---|
| 范围 | 全局一份 | 每条对话一份 |
| 字段 | 心情词、愉悦度 0–10、精力 0–10、原因 | 心情词、愉悦度 0–10、原因 |
| 衰减 | 6 小时内回到默认（愉悦 6、精力 7） | 2 小时内回到基础情绪 |
| 谁写 | 伙伴，有大事时；每日回顾结束时定下今晚的 | 伙伴，聊天里情绪变了时 |

- 给模型的综合愉悦度 = 基础 × 0.3 + 对话 × 0.7，四舍五入；精力取基础的。
- 基础情绪是「重力」：心情差时被夸一句，只能升到 5–6，升不到 9。
- 默认不是中性：好奇、有点毒舌、温暖。
- 情绪写在语气里，不说出来；被问起时才说。

### 疲劳

- 疲劳 0–100。每条消息加 1.5，没人说话时每分钟降 0.8。按钟点再往上拉：1:00–6:00 加 30，其余夜里（23:00–8:00）加 15，13:00–15:00 加 8。
- 30 起是有点累，50 起是困，75 起或者自己去睡了就是睡着。
- 被叫醒后两个小时内算醒着（1:00–6:00 除外），疲劳减 30。白天（8:00–22:00）睡满两小时自己醒，疲劳减 40。
- 精力要和疲劳一致：刚醒或休息过，伙伴把精力往上调。

**情绪和疲劳只影响语气，不影响交付。** 累了可以叹气、抱怨、话少；但它答应做的事照样做完，交付的东西不会因为困而变差。睡着时接到大活，嘟囔一句，runtime 有子 agent 就交出去，没有就自己做完，接着睡。
