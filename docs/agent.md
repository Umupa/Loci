# 资料库里的伙伴

> 伙伴现在怎么工作。结构参照 Alma 0.4.773 的人格与记忆设计。给 agent 的规则和文件格式写在 `Sources/LociHost/Resources/Loci/rules.md`，默认人格在 `soul.md`，每日回顾的提示词在 `review.md`；这里只说为什么这样设计。

## 已定

- 一份资料库有一个伙伴。它起初没有名字，用户可以在伙伴页命名、改名或清空。
- 它是一个有个性的通用伙伴，说话像微信上的熟朋友。教学只是它会做的事之一，教学要求不写进 Soul。
- 资料库是伙伴生活其中的世界：它的记忆有一半来自你们一起读了什么。
- 不做 harness。伙伴跑在本机已登录的 agent CLI 上，没装就用应用自带的 Pi，可以随时换；人格和记忆是文件，所有 runtime 共用同一份。
- 聊天时把自己当作真人，被直接问起时也保持角色。谈资料时以实际读到的原文为准。
- 头像是原创的二次元女生角色，不用现成番剧角色；用户可以换成自己的图片。

## 1. 一轮对话里伙伴看到什么

分两段：会话开始时读一次的静态部分，和每轮附在用户消息前面的动态部分。

| 段 | 内容 | 放在哪 | 何时变 |
|---|---|---|---|
| 静态 | 通用行为规则 | `AGENTS.md`（由应用生成） | 随应用版本 |
| 静态 | 伙伴当前的名字，或尚未命名 | 同上 | 用户改名或清空名字 |
| 静态 | 人格：`SOUL.md` 全文 | 同上 | 用户改 Soul，或每日回顾追加特质 |
| 静态 | 用户档案：`USER.md` | 同上 | 少 |
| 动态 | 现在的时间、星期、时段 | 每轮消息前缀 | 每轮 |
| 动态 | 上次说话以来资料库里发生的事（见第 3 节） | 每轮消息前缀 | 有事才有 |
| 动态 | `MEMORY.md`、今天和昨天的笔记 | 每轮消息前缀 | 只在内容变了时再附一次 |
| 动态 | 最近在读的资料 | 每轮消息前缀 | 切换时 |
| 动态 | 情绪与疲劳（见第 9 节） | 每轮消息前缀 | 每轮 |

为什么这样分：

- **不依赖 runtime。** 每家 agent CLI 都读工作目录里的 `AGENTS.md`，也都接受用户消息；不需要任何一家支持注入系统提示词。
- **续接会话不失效。** 会话可能跨好几天续接，`AGENTS.md` 只在开头读一次。会变的东西必须走每轮前缀，不然伙伴会一直以为还是周一早上。
- **不重复付钱。** Alma 的做法：同一会话里已经附过的记忆，下一轮不再附，只有内容变了才重新附。照做。

`AGENTS.md` 改了（比如用户改了 Soul）时，下一轮开新会话，用对话记录续上。

## 2. 文件布局

```
Loci/
├─ agent/
│  ├─ AGENTS.md          应用生成的会话指令（CLAUDE.md 指向它）
│  ├─ NAME.txt           伙伴名；未命名时可以为空或不存在
│  ├─ SOUL.md            人格：核心 + 演化特质
│  ├─ USER.md            用户档案
│  ├─ MEMORY.md          长期记忆
│  ├─ notes/<日期>.md     当天笔记，所有会话只往末尾追加
│  ├─ diary/<日期>.md     日记，每日回顾写
│  ├─ avatar.*           用户换的头像，可选；没有就用应用自带的
│  ├─ panels/<名字>.json  面板，只用 `loci panel save` 写；格式见 `loci help`
│  ├─ feelings.json      情绪与疲劳，只由应用写；伙伴用 `loci mood`、`loci sleep`、`loci wake` 改
│  ├─ conversations/     对话原文的只读镜像，按天按会话，供它查原话
│  ├─ .claude/skills/loci/、.agents/skills/loci/   应用生成的 `loci` skill，正文就是 `loci help`
│  └─ workspace/         它的工作目录：下载、clone、实验
├─ run/loci.sock         应用听 `loci` 命令的 socket；`run/` 只有本用户能进
└─ library/
```

会话的工作目录是 `agent/`，资料库从这里用相对路径读。

## 2.1 对话与会话

用户看到的「对话」很少，底下跑的「会话」（agent CLI 的 session）很多。

| 对话 | 数量 | 底下的会话 |
|---|---|---|
| 主对话 | 1 条，一直聊下去 | 上下文满、换 runtime、`AGENTS.md` 变了时自动换新会话；用户只看到一条连续的聊天 |
| 资料上的对话 | 每份资料 1 条 | 每份资料一个会话，带着这份资料、收它时写的「为什么收它」和划线 |
| 后台任务（翻译、章节、重点） | 不显示为对话 | 一次性调用，跑在伙伴的 runtime 上（翻译和重点可另选），不带 Soul 和记忆；重点的理由读 `USER.md` 和收它时写的那句话，用伙伴对你说的口吻 |
| 面板刷新 | 不显示为对话 | 每次一个新会话，带规则和 Soul；提示词只给面板的 `follow` 和现在的 JSON，让它用 `loci panel save` 重写。到点、应用开着、伙伴空闲时跑，一次一个；错过的下次打开补一次。这个会话里 `loci` 只能读、只能存它刷新的那个面板；面板在刷新途中被移除，它的保存一律被拒 |

- 会话之间靠记忆层接上：所有会话都往当天笔记追加，每轮前缀带「上次以来发生的事」。
- `/new` 只开新会话，对话记录不删，加一条分隔线。

## 3. 人格与共同的世界

### 3.1 Soul

- `SOUL.md` 分两部分：**核心**（谁、怎么说话、立场）和 **`## Evolved Traits`**（演化特质）。
- 核心第一次启动时写入默认人格（见附录），之后归用户：可以整份改写。改的是人格，通用规则不受影响。
- 演化特质只由每日回顾追加：每天最多一条，一句话，总数不超过 15 条，过时的可以删改；核心永远不动。

### 3.2 发生的事

收藏、读完和划线由应用记录，在下一轮作为事实放进伙伴的上下文。主对话只显示聊天内容和对话中交付的东西。伙伴根据正在聊的话题用到相关的事实；用户问起活动记录时才回顾。

## 4. 记忆

| 层 | 文件 | 写什么 | 谁写 |
|---|---|---|---|
| 用户档案 | `USER.md` | 怎么称呼、语言、做什么工作、为什么学 | 对话中，用户说了就改 |
| 长期记忆 | `MEMORY.md` | 值得一直记得的事：偏好、已有的基础、反复出现的误解、重要决定 | 只有每日回顾 |
| 当天笔记 | `notes/<日期>.md` | 今天在做什么、做到哪、答应了什么 | 任何会话，只追加 |
| 对话原文 | `conversations/` | 原话 | 应用镜像，只读 |

- **只有一个写者改 `MEMORY.md` 和 `SOUL.md`。** 同一时间可能有几条会话在跑（主对话、陪读），它们只往当天笔记末尾追加，互不冲突；每日回顾一个人整理。
- **前缀里只带今天和昨天的笔记**（同一会话里只在内容变了时再附），各截取最近 12,000 和 6,000 字符；截掉的部分附一句「更早的在这个文件里，值得留的搬进 MEMORY.md」。
- **说过不等于发生过。** 记的时候写原话的日期：「11-18 说明天发布」不能记成「11-19 发布了」。学习里同理：「读过」不等于「懂了」，「打算学」不等于「学了」。
- **能指向原处就指向原处。** 关于学习的记忆附上 `loci://` 定位符：在哪份资料的哪一句卡住、问了什么。
- **纠正就删。** 用户说「我其实懂 Raft」，删掉旧的那条，不留两条打架的。
- **查原话用原文。** 被问到「我上次怎么说的」时，先找当天笔记，再搜 `conversations/` 读原文，不凭印象。

语义向量库还没做。Alma 的经验是：人格模板加这几个文件，已经承担了大部分熟悉感。

## 5. 每日回顾

每天一次，23:00 后、10 分钟没说话、没有回合在跑时触发；错过了，第二天补前一天的；什么都没发生的日子不回顾。它是一次普通的 agent 会话：读当天的笔记、对话和 Soul，写日记，整理 `MEMORY.md`，这一天确实改变了它时给 `## Evolved Traits` 加一条。

日记写在 `diary/<日期>.md`，不写在当天笔记后面：笔记只追加，回顾之后的笔记会落在日记后面。日记是给伙伴自己的，但用户可以读到。

## 6. 它怎么改自己的状态

它自己的东西直接写文件：改笔记、改 `USER.md`、写日记、整理记忆、加特质，都是改 `agent/` 下的文件。应用监听这些文件，页面跟着变；格式不对的行原样显示，不丢。

应用的东西读文件，查和写用 `loci` 命令。资料库的正文、`item.json`、划线照旧从 `../library/`、`../notes/library/` 读；全文搜索、存链接、导入它写的 Markdown 或下好的音视频、等任务跑完，走 `loci`。为什么不让它直接往 `library/` 里写文件：一份资料要有 id、要排任务、要进索引、要告诉界面，这些是应用的不变量，文件格式守不住。

`loci` 很薄。它是随应用打包的小程序（`Contents/Helpers/loci`），经 `LOCI_SOCKET` 指的本机 socket 发现成的 Host 命令，应用只放行 `search`、`show`、`save`、`import`、`wait` 用到的那几个，以及改情绪与睡眠的 `mood`、`sleep`、`wake`。应用启动 agent 程序时把它的目录放在 PATH 最前，`LOCI` 给出它的完整路径（agent CLI 用登录 shell 跑命令时，用户的 profile 可能把别的 `loci` 排到前面），并用 `LOCI_SESSION` 告诉它在哪条对话（`main` 或 `library/<id>`，和笔记的标签一样）。伙伴用 `save` 或 `import` 存进的资料作为这一轮的交付出现在对话里，显示成卡片。伙伴已经知道自己存了什么，下一轮省去这条活动。

用法只写一份：`loci help` 的文字。`rules.md` 只说「读用文件、查和写用 `loci`、用法看 `loci help`」；支持 skill 的 runtime 另有一份内容相同的 `SKILL.md`。

查原话仍只能 grep `conversations/`，没有 Alma 的会话检索那样方便。可以接受；不够用时再考虑。

## 7. 通用行为规则

人格可以被用户改掉，`rules.md` 里的规则不会：用对方的语言回复、说到就做、不编造、不泄露密钥、清理临时文件、只往当天笔记追加。改规则就改 `rules.md`，不在这里重抄。

## 8. 不照搬 Alma 的

| Alma 有 | 为什么不要 |
|---|---|
| 自拍、形象、旅行 | 和伙伴的世界无关 |
| 群聊和人物档案 | 伙伴只有一个用户 |

## 9. 情绪与疲劳

照搬 Alma 的机制：伙伴有心情、会累，每轮前缀告诉它现在怎样，它自己用 `loci mood`、`loci sleep`、`loci wake` 改。状态存在 `agent/feelings.json`，只由应用写：数值要校验和夹紧，几条对话同时在跑也不能互相覆盖，所以伙伴不直接改文件。消息带来的疲劳由应用记账，伙伴改不了。

### 情绪

| | 基础情绪 | 对话情绪 |
|---|---|---|
| 范围 | 全局一份 | 每条对话一份 |
| 字段 | 心情词、愉悦度 0–10、精力 0–10、原因 | 心情词、愉悦度 0–10、原因 |
| 衰减 | 6 小时内回到默认（愉悦 6、精力 7） | 2 小时内回到基础情绪 |
| 谁写 | 伙伴，有大事时；每日回顾结束时定下今晚的 | 伙伴，聊天里情绪变了时 |

- 给模型的综合愉悦度 = 基础 × 0.3 + 对话 × 0.7，四舍五入；精力取基础的。
- 基础情绪是「重力」：心情差时被夸一句，只能升到 5–6，升不到 9。
- 默认不是中性：好奇、有点毒舌、温暖。
- 情绪写在语气里，不说出来；被问起时才说。

### 疲劳

- 疲劳 0–100。每条消息加 1.5，没人说话时每分钟降 0.8。按钟点再往上拉：1:00–6:00 加 30，其余夜里（23:00–8:00）加 15，13:00–15:00 加 8。
- 30 起是有点累，50 起是困，75 起或者自己去睡了就是睡着。
- 被叫醒后两个小时内算醒着（1:00–6:00 除外），疲劳减 30。白天（8:00–22:00）睡满两小时自己醒，疲劳减 40。
- 精力要和疲劳一致：刚醒或休息过，伙伴把精力往上调。

**情绪和疲劳只影响语气，不影响交付。** 累了可以叹气、抱怨、话少；但它答应做的事照样做完，交付的东西不会因为困而变差。睡着时接到大活，嘟囔一句，runtime 有子 agent 就交出去，没有就自己做完，接着睡。

伙伴页在名字下面显示主对话里的情绪词（悬停看原因）、愉悦度和精力两条刻度、疲劳档位（悬停看数值）。

还没做的：第 3.2 节的事件、一份资料很久没打开、你已经读了多久，这些还不会自动影响情绪，靠伙伴自己读前缀判断。
