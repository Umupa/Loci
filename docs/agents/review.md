# 审阅

审阅一次改动时读代码，按这个顺序看，前面的不过就不用往后看。

1. **`script/check` 自己跑一遍。** 不信交付说明里贴的输出。
2. **场景。** 说明里列的每条场景，有没有一个测试在说同一件事；测试会不会在实现错的时候照样通过。
3. **边界。** 架构表有没有被改；改了的话理由成不成立。有没有为了过检查而绕路（换个写法躲开正则、把逻辑塞进测试目标、加一个只为转发的类型）。
4. **会被模仿的东西。** 这段代码被照抄十遍，仓库是变好还是变坏。占位实现、重复的辅助函数、含糊的名字、没用到的参数，都要求删掉。
5. **失败的时候。** 外部程序没装、文件被别人改了、磁盘满了、网络断了、用户中途取消，各自会怎样。

结论只有两种：可以合并，或者列出必须改的地方。每个要改的地方，同时提议它能不能变成一条检查（见 `AGENTS.md`「每次被纠正，留下一条检查」）。
