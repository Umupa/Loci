# Loci 1.0：原生 Swift 版（方案设计）

> 2026-11-17 起草。标「待定」的地方还没有决定。代码怎么分见 [architecture.md](architecture.md)，功能叫什么见 [features.md](features.md)。

## 已定的事

| 问题 | 决定 |
|---|---|
| 产品方向 | 双入口：学一个主题（导师），或消化一份材料（资料库）。两者平级 |
| 资料归属 | 资料是独立的原子，不属于也不绑定任何导师；只有课引用资料 |
| 这一轮的媒体 | 视频与技术演讲、播客、文章粘链接即读 |
| 不做 | RSS 与订阅、剪辑与导出 |
| 技术栈 | 全部用 Swift 重写，不保留 Rust 和 WebView 界面 |
| 数据 | 重新设计存储，不兼容旧数据；上云先不做 |
| 平台 | 只做 macOS 26 及以上；Windows 和 Linux 停止 |
| 远程访问 | 1.0 就要对齐现有能力 |
| 命令行 | 去掉 `loci` 命令行；导师通过文件和应用协作 |
| 提问 | 没有内置的「陪读」；打开资料时在侧边选任意一位导师陪读，不产生绑定 |

## 产品

### 两个入口，一套阅读器

开始页只有一个输入框。写一句话是「想学什么」，建一位导师；粘一个链接或拖一个文件是「读这份材料」，进资料库并直接打开。

```
侧边栏              主区
─────────           ──────────────────────────────────
开始                输入框
导师                一位导师 = 一本书：目录、课文、页边问答
  沙箱              
  调度              
资料库              卡片墙 → 打开一份资料
  视频              文章 / 论文：正文居中，页边问答
  播客              视频 / 播客：播放器 + 随播放滚动的文稿
  文章              代码仓库：读码
  代码              
```

- 资料和课文用同一套阅读器、同一种锚点、同一种页边问答。区别只在谁写的：课文是导师写的，资料是别人写的。
- 导师的课文引用资料时，引用是一个定位符，点一下在资料库的阅读器里打开并定位到那一句、那一秒或那几行。
- 资料和导师之间没有绑定。唯一的关系是**课引用资料**：一课的出处是它引用的那几份资料，一门课的资料就是各课出处的并集，不另外维护。
- 从资料库打开一份资料，在侧边选任意一位导师陪读，随时可以换。问答留在这份资料上，每条带着是哪位导师答的。
- 导师陪读过什么、引用过什么都查得到，但那是记录，不是归属。

### 笔记：你读的时候留下的东西

划线、当时的想法、和导师的问答是同一种东西，叫一条笔记：一个位置，加上可有可无的一句想法和一段问答。它们单独存储，既不写进资料，也不写进课文。

阅读器右侧是一个面板，课文、文章、视频、播客都一样：

| 内容 | 面板里的分页 |
|---|---|
| 课文、文章、论文 | 目录 · 笔记 |
| 视频、播客 | 文稿 · 重点 · 笔记 |
| 代码 | 大纲 · 笔记 |

- **笔记**页按原文顺序列出你留下的每一条：划的那句话、你的想法、问了什么、哪位导师怎么答的。点一条，正文或播放位置跳过去。
- **重点**页是导师替这份视频挑的片段，带标题和理由，进度条上同步标出。它是资料的一部分，和你的笔记分开。
- 正文里只留划线本身和一个小记号，内容都在面板里，取代 v0.11 的页边问答。这样文字和音视频是同一套做法。
- 再次打开一课或一份资料，面板里就是上次读它时的全部痕迹。
- 陪读的导师读得到这些笔记，知道你在哪里停过、想过什么。

### 一份视频或播客经过什么

```
链接 / 文件 → 取回 → 转录 → 断句 → 翻译 → 章节与重点 → 可读
```

- 每一步的产物都是资料文件夹里的一个文件，任务可中断、可续做。
- 取回之后就能播放；后面每完成一步，界面多出一样东西，不等全部做完。
- 转录在本机做。翻译、章节和重点走本机的 agent CLI，不另配 API key。
- 文稿每一句都能划线、提问、被课文引用到秒。

### 语音识别与组件

参考 Vimpo 的做法。

**语音识别**用 Whisper，模型按需下载，应用本身不带模型。只给三档，不把七个型号都摆出来：

| 档 | 模型 | 大小 | 适合 |
|---|---|---|---|
| 快 | Base | 约 150 MB | 发音清楚的英语讲解，几乎秒出 |
| 推荐 | Large v3 Turbo 压缩版 | 约 570 MB | 大多数情况；中文和口音也可靠 |
| 最准 | Large v3 | 约 3.1 GB | 嘈杂、多人对话 |

- 第一次加视频或播客时，如果没有模型，就在那张卡片上提示下载推荐档，不用先去设置里找。
- 自动识别语言；断句在转录之后单独做一步。
- 引擎在 whisper.cpp 和 WhisperKit 之间选，α0 的视频验证里实测速度和中英文质量后定。系统自带的语音识别作为没下载模型时的备选，同样实测后决定留不留。

**组件**是应用自己不实现、要调用的外部程序：

| 组件 | 用途 | 来源 |
|---|---|---|
| yt-dlp | 取回视频和播客 | 系统里已有（如 Homebrew）就用它，没有则由 Loci 下载管理 |
| FFmpeg | 转封装、抽音轨 | 由 Loci 管理 |
| JavaScript 运行时 | yt-dlp 解析部分站点需要 | 由 Loci 管理 |

- 都装在 `~/Library/Application Support/Loci/` 下，和模型放一起，不改动系统，也不进 `~/Loci`（那里只放用户的内容）。
- 设置里一页列出每个组件的版本和来源，可更新、可重新检测。yt-dlp 失效得快，取回失败时直接提示更新。
- 这些组件只有用到视频和播客时才需要，不影响只读文章和课文的人。

### 需要修改的原则

- 「应用里不写爬虫」改为：**取回一个确定的链接**由应用做（yt-dlp、正文提取、播客音频地址、论文 PDF），这样粘贴后几秒内就能开始读；**找什么值得读**仍然是导师的事。
- 「一手材料优先」不变。资料库就是一手材料的家。

### 待定

- 不搬到原生版的功能清单（Projects、habit、聊天背景与壁纸、社区 Feeds、托盘等），在 α1 开始前逐项确认。

## 设计

Loci 的辨识度是纸墨单色加一个导师色，保留。要换的是质感的来源：现在靠 CSS 模拟，以后靠系统。

| 方面 | 做法 |
|---|---|
| 外框 | 侧边栏、工具栏、弹层用 macOS 26 的系统材质；内容区保持纸面，不透明 |
| 配色 | 亮色是纸，暗色是墨夜，两套都单独调，不做简单反色；唯一强调色仍是导师色，资料库用中性墨色 |
| 图标 | 界面图标换成 SF Symbols，缺的按同一线宽自绘成自定义符号；应用图标按 macOS 26 的分层图标格式重做 |
| 字体 | 界面用系统字体；阅读用霞鹜文楷与 Literata |
| 动效 | 系统弹簧动画；卡片到阅读器是同一个元素的连续过渡；选中、悬停即时响应 |
| 控件 | 用系统控件和系统行为：设置是独立的设置窗口，菜单栏完整，快捷键符合惯例 |

流畅度定成可以测的预算：

| 指标 | 预算 |
|---|---|
| 冷启动到可操作 | 0.5 秒内 |
| 长课文、长文稿滚动 | 120 帧不掉 |
| 打开一份已缓存的资料 | 100 毫秒内出首屏 |
| 流式回复 | 不引起整页重排 |
| 空闲内存 | 200 MB 内 |

视觉方向先出并排草图再做：侧边栏、开始页、资料库卡片墙、播放器加文稿、课文阅读器、应用图标，各两到三个方案。

## 架构

```
┌──────────── Loci.app ────────────┐
│ LociUI  SwiftUI + AppKit/TextKit │
└───────────────┬──────────────────┘
                     Host 协议（一套有类型的命令）
                ┌──────────┴───────────┐
           LocalHost               RemoteHost ── 加密通道 ── 另一台 Mac 的 LocalHost
                │
   ┌────────┬───┴────┬─────────┬─────────┐
 Store    Agents   Media     Code     Remote
```

- **界面只认 Host 协议。** 本机是进程内调用，远程是同一套命令走加密通道。远程对齐靠这一层保证，不是事后补的功能；以后的 iPhone 和 iPad 端也只是换一个界面。
- **命令层是唯一的入口。** 界面和远程都走它。测试和评测直接调这一层，不经过界面。
- **导师通过文件和应用协作，没有命令行。** 导师写课文、改目录、列出要用的资料，都是改自己文件夹里的文件；应用监听到变化后去做剩下的事（比如取回课文出处里新写的链接）。
- **核心不依赖界面。** 会话驱动在 `Agents` 里，关掉窗口照样跑，这就是之前想做的无头主机。

| 模块 | 职责 | 依赖 |
|---|---|---|
| `LociModel` | 值类型、定位符、命令的请求与响应 | 无 |
| `LociStore` | 文件读写与监听、SQLite、全文索引、变更日志 | GRDB |
| `LociAgents` | 各家 agent CLI 的协议驱动、会话、权限 | 系统的子进程 API |
| `LociMedia` | 取回、转录、断句、翻译、章节与重点的任务队列 | AVFoundation、Whisper、yt-dlp、FFmpeg |
| `LociCode` | 符号大纲、跳转定义、查找引用 | tree-sitter |
| `LociRemote` | 配对、加密通道、中继、设备组 | CryptoKit、Network |
| `LociHost` | 命令层；`LocalHost` 与 `RemoteHost` | 以上全部 |
| `LociEval` | 评测：调命令层建导师、等课文、评分；不随应用发布 | `LociHost` |
| `LociUI` | 界面与设计系统 | SwiftUI、AppKit、PDFKit、AVKit |

其他选择：

- **阅读器**用 AppKit 加 TextKit 2 自绘：跨段落选区、划线、锚点、页边问答、流式 Markdown 都压在这一个组件上。Markdown 用 swift-markdown 解析。
- **Mermaid 和公式**先用 WKWebView 小岛兜底，渲染成图后贴进正文。
- **状态**用 `@Observable` 和 Swift Concurrency，不引入额外的架构框架。
- **分发**走 Developer ID 签名公证加 Sparkle 更新，不上 Mac App Store：要启动用户自己装的 agent CLI，不能进沙盒。
- **仓库**：原生版在 `native` 分支，从一开始就不带 Tauri 代码；Tauri 版留在 `main`，只作行为参考。1.0 发布时 `native` 成为 `main`。
- **工程**：只用 SwiftPM，没有 Xcode 工程；应用包由脚本组装。

## 数据

### 原则

1. **内容是文件。** 人能读，导师（agent）能直接写。
2. **状态在数据库。** 高频变化、需要查询、需要同步的东西。
3. **索引可重建。** 全文搜索和缓存删掉后能从文件和状态重新生成。
4. **大文件永远只在本机。** 上云的只可能是元数据和小文本。

### 目录

```
~/Loci/
├─ library/
│  └─ <短名>-<id>/
│     ├─ item.json           种类、标题、作者、来源链接、语言、时长、版本或 commit、内容哈希
│     ├─ content.md          文章正文；论文另有 content.pdf
│     ├─ media.mp4|m4a       音视频；可以只链接外部文件
│     ├─ transcript.json     文稿：句、起止时间、说话人
│     ├─ translations/<语言>.json|md
│     ├─ outline.json        章节与重点
│     └─ repo/               代码仓库的工作树（种类为仓库时）
├─ mentors/
│  └─ <短名>-<id>/
│     ├─ mentor.json         名字、头像、颜色、provider、模型、权限
│     ├─ SOUL.md · memory/
│     ├─ catalog.yaml        目录：章 → 课
│     ├─ lessons/<slug>.md   课文；开头列出处（资料 id 或待取回的链接），正文里的引用写成定位符
│     ├─ glossary.yaml
│     └─ workspace/          导师的工作目录
├─ notes/
│  └─ <内容 id>.jsonl        这份内容上的笔记，一行一条，只追加
└─ loci.sqlite
```

- 导师想用一份新资料，就在课文开头的出处里写一个链接；应用取回后放进资料库，并把链接换成资料 id。资料文件夹里不记录谁用过它。
- 笔记按内容分文件，放在资料和导师之外：资料可以重新取回，课文会被导师修订，笔记都不受影响；删掉一份资料时笔记是否一起删，由你选。
- 一条笔记：定位符、划线的原文、你的想法、问答（问题、回答、哪位导师）、时间。修改和删除也是追加一行。
- 应用生成的标识（导师、资料、笔记）用 UUIDv7；导师手写的标识（课）用短名（slug），它同时是课文的文件名。agent 写不出 UUID。
- 导师、资料用 UUIDv7 作 id。文件夹名带一个可读的短名，方便人和 agent 浏览；以文件里的 id 为准，改名不破坏引用。
- 资料的种类：文章、论文、视频、音频、仓库。新种类只加一种阅读器和一种定位方式。

### 定位符

笔记、课文引用、阅读位置，全部用同一种定位符：

```
loci://library/<id>#t=204.1,207.8          音视频：起止秒
loci://library/<id>#quote=<原文>&pre=<前文>&post=<后文>   文本：引文加上下文
loci://library/<id>#page=3&rect=…           PDF
loci://library/<id>#path=src/vm.rs&L=12-40&rev=<sha>     代码
loci://mentor/<id>/lesson/<id>#quote=…      课文
```

文本用引文加上下文而不是字符偏移，原文重新抓取或课文修订后还能重新对上；对不上时标成失效而不是指错地方。

### 数据库

| 表 | 内容 | 来源 |
|---|---|---|
| `item` · `mentor` · `lesson` | 资料、导师、课的镜像，用来查询 | 文件 |
| `citation` | 哪一课引用了哪份资料的哪一处；从课文解析出来 | 文件 |
| `note` | 笔记的镜像，用来按内容、按导师、按时间查，以及全文搜索 | 文件 |
| `reading_state` | 每份内容的位置与读完标记 | 数据库 |
| `conversation` · `message` | 对话，只追加 | 数据库 |
| `job` | 媒体任务的阶段与进度 | 数据库 |
| `search` | 全文索引 | 可重建 |

### 上云

先不做。只保留两个不花成本的习惯，以后要做时不用改表：每个实体有全局唯一的 id，每行有修改时间。变更日志、冲突规则、后端选择都不做。

## 远程访问

能力对齐现有版本：配对、端到端加密、经中继连通不同局域网、设备组、客户端缓存看过的内容。实现全部重写：

- 远程客户端就是同一个应用连到 `RemoteHost`，没有单独的客户端代码。
- 加密只用 CryptoKit 里现成的原语（X25519、Ed25519、HKDF、AES-GCM）。现有配对用的 SPAKE2 在 CryptoKit 里没有，不手写：配对改为二维码或配对码交换公钥，再由双方核对一串短验证码。协议可以不兼容旧版。
- 每次调用约 0.6 秒的中继延迟是已知问题，重写时把多次小调用合并成订阅：客户端订阅一个视图需要的数据，主机推变化。
- 中继服务是否沿用现有的，待定。

## 风险与验证

动手前先做四个限时验证，每个一到两天，结论决定方案是否调整：

| 验证 | 通过标准 |
|---|---|
| 阅读器 | 霞鹜文楷长文流畅滚动；跨段落选中、划线、锚点重新定位；页边问答；Markdown 流式到达不跳动 |
| 驱动 | Pi 和 Grok 的流式会话、工具调用、权限询问、中断与恢复在 Swift 里跑通 |
| 视频 | 一段 20 分钟的英文演讲：下载、本机转录、文稿随播放同步；记录转录耗时和中英文质量，定默认引擎 |
| 远程 | 两台 Mac 经中继配对并跑通一条命令和一个订阅 |

其他风险：

- **重写期间功能停摆。** Tauri 版冻结在 0.11.x，只修影响使用的问题。
- **驱动是最大的一块**（现有约 2.9 万行 TS）。十家 agent CLI 全部要兼容：先做 Pi 和 Grok，再做 Claude Code 与 Codex，其余随后；每家都用现有测试用例作对照。测试和评测跑在 Pi 上。
- **公式和图**没有成熟的原生渲染，WebView 兜底可能长期存在。
- **原生平台自己的怪行为**（后台线程碰界面、未激活窗口的点击）不会因为换框架消失，但 Swift 的并发检查能在编译期拦住一部分。

|---|---|---|---|

## 现有功能的去向（α0-9，已确认）

2026-11-17 盘点 0.11 的全部功能后确认。没列出的细节随所属功能走。

### 搬

| 范围 | 内容 |
|---|---|
| 导师 | 开始页；Mentor 与 Lens 两个模板；Soul 编辑；记忆；头像、颜色、名字；心跳；上下文轮换；长对话分页；每位导师的设置；删除；回来卡片 |
| 课程 | 章与课；目录；知识树；首章写出前的进度；请求写未写的课；下一课与自动已读；修订可见；术语表；对比课；考考我 |
| 阅读 | Markdown、PDF、代码、图片；记住位置；选区工具条；按块划线与提问；引用跳转并闪一下；阅读排版；把「正在读」带给导师 |
| 对话 | 记录与输入框；附件；排队与插话；停止；@ 提及；`/new`、`/compact`；模型与权限选择；审批；提问卡；各类卡片；计划与任务预览；上下文用量；登录引导；对话内查找；中断回合恢复 |
| 读码 | 钉住 commit；符号大纲、跳定义、查引用（六种语言） |
| 翻译 | 译文、原文、对照；全局与每位导师的学习语言 |
| 远程 | 配对、设备组、加密通道、中继、主机文件浏览与上传、离线缓存、主机不睡、设置按主机或本机划分 |
| 系统 | 菜单栏、通知、更新、双渠道、粘贴文件与截图、⌘K 搜索、现有快捷键 |

### 搬，但换了做法

| 现在 | 原生版 |
|---|---|
| 每位导师自己的资料库（Courses / Sources / Notes / Files 四段） | 全局资料库；导师页只有目录和课 |
| 一手资料与导读存在导师文件夹里 | 一手资料进资料库；导读并入课文 |
| 页边问答、课末「在这课问过的」、一门课的高亮汇总 | 右侧面板的笔记页 |
| 高亮与批注存在数据库 | `notes/` 下的文件 |
| 导师通过命令行和 app 动作操作应用 | 导师改自己文件夹里的文件 |
| 22 套主题、色相与饱和度滑杆、玻璃与模糊滑杆 | 纸与墨夜两套，跟随系统明暗；强调色是导师色 |

| 界面英文、设置页中文 | 全应用中英两种语言 |
| 十家 agent CLI，各写一套驱动 | 十家都兼容，按协议合并成五套：Pi 系 RPC（Pi、omp）、ACP（Grok、Antigravity、Cursor、fx、Hermes）、Claude Code、Codex、OpenCode。顺序：Pi 和 Grok 最先，1.0 前全部补齐 |

### 不搬

- `loci` 命令行与本地控制通道。
- 自由书写的笔记文档（所见即所得编辑器、存到笔记）。新的笔记是读的时候留下的划线、想法和问答。
- Dock 角标上的数字，只留通知。
- 导师的「全部资料」入口。从课的出处进资料，从资料反查引用它的课。
- 对话背景、主题壁纸、输入框吉祥物、界面缩放。
- 文件树里的文件操作（新建、改名、移动、删除）：交给访达；工作目录只读浏览。
- Windows 与 Linux 专用的托盘、模拟菜单栏、窗口按钮、子进程管理。
- 遗留代码：Projects、置顶会话、会话全文搜索、按项目的 provider、多账号、habit、画布清理、旧课型、0.3 到 0.4 的迁移。

### 推迟到 1.0 之后

- 导师导出与导入（文件夹本身可以直接拷贝）。
- 委派子会话。
- 中途换 provider 的自动交接、`/btw`、`/draft`、提示词大纲、链接预览、设置搜索、多窗口、提示音。
