# 界面语言

Loci 支持英文和简体中文。默认跟随系统语言，也可在“设置 → 通用 → 界面语言”中选择。切换立即生效，选择会保存在本机并同步到其他已打开的窗口，不会重新挂载工作区或清空草稿。系统语言按偏好顺序匹配英文或中文，其他语言回退到英文；中文地区变体目前统一使用简体中文。

会话内容、用户命名、模型名称、文件路径、命令和协议标识保留原文。第三方 CLI 返回的消息也保留原文。

## 添加文案

- 在 `src/shared/i18n/zh-CN.json` 中维护英文原文到简体中文的映射。英文原文同时用作缺失翻译时的回退。
- 渲染组件使用 `useLocale()` 订阅语言变化，再用 `t("原文")` 获取文案。缓存含文案的 `useMemo` 结果时，将当前语言纳入依赖。
- 动态内容使用完整句子和 `{0}`、`{1}` 等占位符，不按英语词序拼接中文，也不把用户输入当作翻译键。
- 模块级展示常量使用 getter 延迟读取译文。持久化数据与服务商模型目录保留原值，在界面上翻译。
- 日期、时间使用当前 `getLocale()`。Excalidraw 通过 `langCode` 使用自己的语言包。
- 原生菜单复用同一份词表，切换语言时保留快捷键设置。

用语以清楚、自然为先：`session` 为“会话”，`workspace` 为“工作区”，`pane` 为“分栏”，`archive` 为“归档”。`Parked` 表示标签页可找回，译作“已收起”；`Steer` 表示立即给当前任务补充消息，译作“立即补充”。权限说明需完整保留审批边界和生效时机。

## 验证

`src/shared/i18n/locale.test.ts` 检查语言选择、跨窗口同步、占位符、中文搜索、日期及草稿保留。界面文案改动还应通过既有组件测试。

运行 `npm run dev` 后，打开 `/scripts/acceptance/i18n.html` 可检查真实设置页与权限菜单的布局。该预览使用模拟数据，不访问用户数据库或启动智能体。检查中文、英文、长项目名和窄窗口；在输入框写入草稿后切换语言，确认内容不变。
