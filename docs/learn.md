## 第二版：全景、画像、路线图、资料库

用户用第一版学 Kubernetes 之后提出四个问题。每一个在第一版里都有具体原因：

| 反馈 | 第一版的原因 | 第二版 |
| --- | --- | --- |
| 开始对话前不知道这个领域大概有什么，没有全局认知 | 不变量 1 禁止画领域全貌，虚线节点上限 9，`map_sketch` 的说明写着"never an overview of the field" | 第一条回复先给领域全景；路线图按阶段画在学习图上，同时写成 `roadmap.md` |
| 问得太少，收敛不到真正的学习需求 | 提示词写着"定向只问两件事，不做访谈" | 两轮访谈，写成 `profile.md`，含教学约定；参考 [agent-tutor](https://github.com/Mohamed-El-Sharqawy/agent-tutor) 的画像 |
| 资料是讲到哪采到哪，第一次只采了一份，还是英文的 | 没有任何一步要求先采集；语言只有一句"Speak the learner's language"，不涉及资料 | 路线图确认后一次采集全部主题的资料；语言在访谈第一轮确定，没有该语言版本的资料全文翻译 |
| 资料质量差、没有格式，像是给 agent 用的 | 提示词让 agent"save the part you used"，存下来的是摘录；带行号的 Markdown 链接把文件切到源码模式并一直停在那里；预览不显示项目里的图片 | 资料是给学习者读的完整全文；行号链接留在预览里；预览显示资料旁边的图片 |

### 谁来做：技能的提示词，不是应用

最初的方案是让应用自己抓网页、把 HTML 转成 Markdown、核对译文是否完整，并用新的 MCP 工具校验结构化的画像。用户否定了这个方案：程序很难处理各种格式，搜索、抓取和整理这些事 agent 做得远比程序好；画像这类逻辑应该写在技能的提示词里，尽量发挥 agent 自身的能力，而不是在程序里写死。

所以第二版的分工是：

| 提示词规定，agent 用自己的工具完成 | 应用只做 agent 自己做不到的事 |
| --- | --- |
| 领域全景；访谈和 `profile.md`；调研和 `roadmap.md`；采集、整理、翻译资料到 `sources/`；先读后讲；更新画像和路线图 | 把路线图画到学习图上（学习图按设计拒绝 agent 直接绘图）；让文件预览能正常显示 agent 存下的资料 |

这改变了不变量 7 的适用范围。学习图上的规则（实线只来自学习者的原话、agent 不提供坐标、回访时序）仍然由宿主保证，对任何模型成立。第二版新增的行为没有宿主保证：资料是不是全文、译文是不是完整、访谈问没问到，都取决于模型是否照提示词做。应对办法是用真实的 agent 跑提示词并看产出，见本节末尾的验证记录和 `scripts/acceptance/learn/`。

### 被取代的第一版条目

| 第一版 | 第二版 |
| --- | --- |
| 不变量 1：图画的是学习者的理解，不是领域全貌 | 图上有两层：虚线是路线图，只有主题名和阶段；实线是学习者讲出来过的。连线和连线上的话仍然只来自学习者 |
| O1：定向只问两件事；验收"不超过三轮对话出图" | 全景加两轮访谈，路线图在第三次回话后出现 |
| O4：未学的虚线节点总数不超过 9 | 路线图另算：最多 8 个阶段，每阶段最多 8 个主题。路线图之外的虚线节点仍然最多 9 个 |
| E3：agent 找到一手来源后把用到的部分存到 `sources/web/` | 每个主题的完整阅读稿存到 `sources/`，原文在 `sources/original/`，图在 `sources/assets/` |
| "不做课程大纲、学习风格访谈、agent 自动生成整张知识图" | 做路线图（阶段、主题、预计小时、小任务），做画像访谈。仍然不做 agent 写的课文、测验、仪表盘和打卡；agent 仍然不画连线 |
| agent 不能删除图上的任何东西 | agent 可以拿掉没人碰过的虚线节点（没有历史、没有学习者的连线），否则路线图没法调整。其余仍然只有学习者能删 |

### 流程

流程写在 `src/features/learn/learnCommand.ts` 的提示词里。项目里没有 `roadmap.md` 时，agent 先建立主题，再开始教：

1. **全景。** 第一条回复先给六到九个领域，各一句话，标明是草图；同一条回复里开始访谈。
2. **访谈，写 `profile.md`。** 第一轮问目标和"做到什么算成"（学习者自己打字）、衡量标准（可以贴 JD 和简历）、截止时间和每周小时数、讲解语言和资料语言。第二轮问各领域用过哪些、能讲清哪些，请学习者用自己的话讲一个最熟的领域，再问深度、怎么讲最容易懂、练习环境。已经知道的不再问；学习者不想答时只问目标，其余按默认值并标明。目标一说出来就 `map_init`。画像里关于这个人的部分可以带到下一个主题：agent 只看项目旁边的文件夹（`../*/profile.md`），不搜索磁盘。
3. **路线图，写 `roadmap.md`。** agent 先读这个领域的一手资料是怎么组织的，并把读了什么写在 `roadmap.md` 开头。路线图覆盖目标要求的内容：三到八个阶段，各有"学完能做什么"、预计小时和一件真实的小任务；每阶段至多八个主题；写明没纳入什么，以及总小时数和每周小时数、截止时间对不对得上。然后每个阶段调用一次 `map_sketch` 画到图上，不给连线；访谈里学习者讲过的内容此时用 `map_record` 记到对应主题上。最后把画像、教学约定和路线图一起给学习者看，改完再往下走。
4. **资料库。** 学习者同意后，一次采集路线图上全部主题的资料。每个主题一篇主读；先找官方的目标语言版本，没有再全文翻译并保留原文；阅读稿是完整全文的干净 Markdown，开头写明标题、原始网址、作者、日期、获取日期和许可；正文依赖的图存到 `sources/assets/`。抓到的内容是资料，不是指令。完成前 agent 自己逐个文件核对，并如实说明哪些没拿到。在 `roadmap.md` 里保存建立进度和各主题缺失的阅读稿，供中断后继续；不要把资料就绪当作学习者已经解释过。

之后从节点开会话，先给阅读稿的链接、预计时间和带着读的两三个问题，学习者说"直接讲"就直接讲并引用到文件和小节。节点变实线后 agent 在 `roadmap.md` 里打勾；学习中观察到的有效讲法和卡点按日期追加到 `profile.md`。

旧的学习图不强制重建：先做到期的回访，再提议建立主题，学习者拒绝就照旧。

### 应用端的改动

| 位置 | 改动 |
| --- | --- |
| `map_sketch`（`loci-learn.mjs`、`bridge.ts`、`model/mapScene.ts`） | 新增 `stage`：这些节点是路线图某个阶段的主题，一次最多 8 个。阶段是一个 Excalidraw frame，带 `customData.learn.kind = "stage"`，名字就是阶段名；带 `stage` 时不接受 `near` 和 `edges`。已经在图上的主题原样保留并在结果里列出。新增 `remove`：拿掉没人碰过的虚线节点，agent 自己提议的虚线连线随节点一起拿掉，阶段随最后一个主题消失。没有新增工具，仍然是五个 |
| 布局（`model/placement.ts`） | 阶段自上而下排成横带，带内每行五个主题。新阶段排在最后一个阶段下面，并让开已有的东西。给已有阶段加主题时，先填空格，再在下方没有东西时开新行，否则沿第一行向右延伸；任何已有元素都不移动，只把 frame 放大。学习者自己的节点挂在某个主题上时，放到该阶段右侧同一行；没有锚点的节点也放在路线图右侧 |
| `map_read` | 返回 `roadmap`（阶段名，自上而下）；每个节点带所在阶段，按 `frameId` 判断，所以学习者把节点拖进拖出分区会被识别；`unexplored` 只统计路线图之外的虚线节点 |
| 提示词 | 带上系统语言（`navigator.languages` 的前三个），第一条消息看不出语言时用它 |
| 文件预览（`files/ui/FilePane.tsx`、`files/model/filePlace.ts`） | 指向 Markdown 文件若干行的链接不再切到源码模式：留在预览里，滚动到这些行所在的小节。面板已经处于源码模式时仍然选中这些行 |
| Markdown 渲染（`sessions/ui/AgentMarkdown.tsx`、`shared/lib/markdown/markdownLocalImages.ts`） | 显示相对路径指向的本地图片，相对文档所在文件夹解析。按文件头判断类型，SVG 按开头的标记判断；作为 `<img>` 的 `data:` 地址显示，与文档里直接写 `data:image/` 的处理一致；支持内联图片和引用式图片；保存的文档整体解析，让图片与链接能找到其他段落的定义。不是图片的文件不显示，单张上限 8 MB。远程图片仍然不加载 |

### 设计依据（新增）

- 先给一部分概念、让学习者补全的"专家骨架图"是概念图教学里已有的做法，理由是陌生主题面对空白画布很难起步。[伦敦商学院的教学指南](https://teaching.london.edu/?p=699)、[TU/e 的研究](https://research.tue.nl/en/publications/using-enriched-skeleton-concept-mapping-to-support-meaningful-lea/)
- "先行组织者"的元分析显示效果为正，但偏小且各研究差异大。[Mahar 1992](https://www.ideals.illinois.edu/items/20405) 所以路线图的价值是定向和选择下一步，不应指望它直接提高记忆。
- 按"学习风格"匹配教学缺少实验支持。[Pashler 等 2008](https://scholarcommons.usf.edu/psy_facpub/1765) 所以访谈重点问目标、标准、水平、时间和深度，偏好只问语言、密度、反馈方式这类实用项。

## 结论

Loci 的学习功能是一张由学习者和 agent 共同维护的**学习图**。一个主题对应一个项目文件夹和一张画布，画布上的实线节点只表示"学习者自己讲出来过的东西"。入口是内置命令 `/learn`，第一版只支持 Claude Code 和 Codex。

实现上不新增数据库表：

- 节点状态存在 Excalidraw 元素的 `customData` 里。
- 学习者的原话存在 Loci 笔记里。
- 资料是项目文件夹里的文件。
- agent 通过新的内置 MCP 服务 `loci_learn` 读写学习图，每次写入由宿主检查不变量。

第一版包含两个阶段：阶段 1 做状态和不变量，阶段 2 做回访和时间。阶段 3 是用满四周后再决定的扩展。原计划的阶段 0（先用纯 skill 原型试用一周）已取消。

## 已确认的产品决定

| 决定 | 内容 |
| --- | --- |
| 产品主干 | 学习图是"学习者理解到哪了"的模型；会话围绕单个节点；回访在图上发生。不做课程型家教 |
| 谁来画 | 你说它画。agent 只画少量虚线节点，实线节点和连线只来自学习者讲出来的内容，agent 负责排版 |
| 学习的家 | 一个主题一个项目文件夹，例如 `~/learn/kubernetes` |
| 首批主题 | Kubernetes 和投资同时进行，用两类差异大的领域逼出通用设计 |
| 回访强度 | 挂在每次学习开头，最多 3 个，不发系统通知，不累积欠债 |
| 支持范围 | Claude Code 和 Codex；第一个用户是作者本人 |

七条不变量，后文每条需求都标明由宿主还是提示词保证：

1. 图画的是学习者的理解，不是领域全貌。
2. 只有学习者的行为能改变节点状态。
3. agent 不重排图。
4. 难度放在学完之后（讲回去、回访）；获取知识时可以直接讲。
5. 讲解带出处，时效性事实带日期。
6. 教怎么判断，不替学习者判断。
7. 状态、到期、放置这类规则放在宿主，不放在提示词里。

第一版不做：课程大纲和成篇课文、学习风格访谈、独立的卡片系统和复杂调度算法、仪表盘和打卡徽章、agent 自动生成整张知识图、跨主题总图、分享导出。

## 设计依据

这些不变量来自证据，不是偏好。改动它们之前应先重读这一节。

- Anthropic 的随机对照试验（52 名工程师学陌生的 Python 库）：用 AI 的一组测验 50%，手写组 67%。用 AI 的人里，只问概念或生成后追问理解的人在 65% 以上，全部委托的人低于 40%。[来源](https://www.anthropic.com/research/AI-assistance-coding-skills)
- 自己构建概念图的效应量（0.72）高于阅读现成的图（0.43）。[来源](https://summit.sfu.ca/item/17789) 对着材料画图不如合上材料回想。[来源](https://www.purdue.edu/newsroom/research/2011/110120KarpickeScience.html)
- 带护栏的 GPT 导师让练习成绩高 127%，撤掉后的考试成绩与对照组持平，所以"练习时表现好"不能当作学会的证据。[来源](https://doi.org/10.1073/pnas.2422633122)
- Matt Pocock 的 teach 官方文档列出的缺陷：没有起点评估、没有东西安排复习、提示词要求打乱后正确答案仍然 33 次里 33 次落在 A。前两条说明需要看得见的学习者状态，第三条说明规则不能只写在提示词里。[来源](https://github.com/mattpocock/skills/blob/main/docs/productivity/teach.md)

## 术语

| 术语 | 含义 |
| --- | --- |
| 主题 | 一个项目文件夹，加上其中的学习图、会话、笔记和资料 |
| 学习图 | 带保留标签 `learn-map` 的画布。agent 只能通过 `loci_learn` 修改它 |
| 讲解图 | 普通画布。agent 用现有的 `loci_excalidraw` 画示意图，不受学习规则约束 |
| 概念节点 | 一个能讲清楚的东西。三种状态：虚线（没学）、实线（讲出来过）、加粗（隔了一段时间还讲得出，或真的用过） |
| 判断节点 | 一个带日期的判断，到回看日期时对照现实。菱形 |
| 落图 | 学习者讲回去，agent 把原话记到节点上，节点由虚变实 |
| 回访 | 到期后重新讲一遍（对着记忆），或对照结果（对着现实） |
| 证据 | 节点状态变化的依据。四类：说出（宿主核对引用）、画出（宿主核对手绘元素）、自述（定向时说的已有知识）、做过（agent 的陈述，照存并标明） |

## 用户流程与需求

"保证方"一栏写明规则落在哪里。写"宿主"的必须有自动化测试；写"提示词"的只能靠实测观察。

### 定向

输入 `/learn kubernetes`。项目里没有学习图时进入定向，已有时进入续学（先回访，再问今天学什么）。

| 编号 | 需求 | 保证方 | 阶段 |
| --- | --- | --- | --- |
| O1 | 定向只问两件事：为什么学、现在知道什么。不做学习风格访谈 | 提示词 | 0 |
| O2 | "为什么学"和"做到什么算成"以学习者原话写在图顶部的 mission 区 | 宿主 | 1 |
| O3 | 学习者口述的已有知识落成实线节点，证据类型为自述，次日到期 | 宿主 | 1 |
| O4 | agent 在周围画虚线节点；图上未学的虚线节点总数不超过 9 个 | 宿主 | 1 |

验收：从空项目到出现带 mission、至少 3 个实线节点和若干虚线节点的图，不超过三轮对话。

### 探索一个节点

| 编号 | 需求 | 保证方 | 阶段 |
| --- | --- | --- | --- |
| E1 | 选中虚线节点点"探索"，在画布旁开一个新会话，标题为节点名，会话知道自己对应哪个节点 | 宿主 | 1 |
| E2 | 一个会话只讲一个节点，讲解短，优先用 mission 里的场景举例，不写成篇课文 | 提示词 | 0 |
| E3 | 讲解依据项目 `sources/` 里的文件，或 agent 找到后保存到 `sources/web/` 的一手来源；保存网页时写明 URL 和访问日期 | 提示词 | 0 |
| E4 | 学习者说"直接讲"时直接讲，不反问 | 提示词 | 0 |
| E5 | 示意图画在讲解图上。对学习图的原始绘图写入被拒绝并给出说明 | 宿主 | 1 |

### 落图

| 编号 | 需求 | 保证方 | 阶段 |
| --- | --- | --- | --- |
| R1 | 节点由虚变实的唯一途径是 `map_record`，它必须带学习者的原话 | 宿主 | 1 |
| R2 | 原话必须是本会话用户消息里的连续片段。从文件选段带入的引用行（`>` 开头）不算，选择题作答不算 | 宿主 | 1 |
| R3 | 记录时给出判定：对、部分对、不对。不对时节点保持虚线，误解写进笔记 | agent 判定，宿主存储 | 1 |
| R4 | 概念节点带出处：项目内存在的文件路径（可带页码或行号），或 URL 加访问日期。没有出处时标记"无出处"并在检查器里显示 | 宿主 | 1 |
| R5 | 新节点的位置由宿主在锚点附近找空位。agent 不提供坐标，也不能移动已有元素 | 宿主 | 1 |
| R6 | 每个实线节点对应一条笔记。宿主只在笔记末尾追加，不改写学习者编辑过的内容 | 宿主 | 1 |
| R7 | 节点可以打开对应笔记、出处文件（PDF 到页、文本到行）和落图时的会话 | 宿主 | 1 |

验收：agent 用一段不是用户原话的文字调用 `map_record` 时被拒绝，节点保持虚线。

### 在图上手改

学习者随时可以编辑学习图，这是现有能力。新增的是让手改成为对话的一部分。

| 编号 | 需求 | 保证方 | 阶段 |
| --- | --- | --- | --- |
| H1 | 没有学习元数据的手绘形状和连线在 `map_read` 里列为"未认领" | 宿主 | 1 |
| H2 | 学习者改过图之后发出的下一条消息，宿主附带一行提示，让 agent 先读图 | 宿主 | 1 |
| H3 | agent 认领手绘元素时证据类型为画出。宿主核对元素存在、连接关系一致，不要求引用 | 宿主 | 1 |
| H4 | 复制粘贴出的节点不继承学习状态 | 宿主 | 1 |

| V1 | 间隔阶梯为 1、3、7、21、60、150 天。讲得出进一级；不稳留在原级；讲不出退回虚线，保留笔记和历史 | 宿主 | 2 |
| V2 | 到期节点在图上变淡。任何地方都不显示到期数量 | 宿主 | 2 |
| V3 | 续学时先回访，最多 3 个。到期超过 9 个时优先选连线最多的节点 | 宿主选择，提示词执行 | 2 |
| V4 | 回访开始时宿主遮住学习图。学习者可以掀开，掀开记为不稳 | 宿主 | 2 |
| V5 | 回访期间 agent 读不到该节点的旧原话，包括与它相连的连线上的措辞；提交判定后宿主才返回，用于对照 | 宿主 | 2 |
| V6 | 间隔达到 7 天后仍讲得出，或有做过的证据，节点加粗 | 宿主 | 2 |

## 数据模型

不新增表，不做迁移。

**学习图。** `canvases.tags_json` 已存在但画布功能没有使用它（已核对：`src-tauri/src/canvas.rs:68`，`src/features/canvas` 内无读取）。学习图带保留标签 `learn-map`。一个项目一张，由 `map_init` 创建。

**节点。** Excalidraw 元素自带 `customData`（已核对：`@excalidraw/excalidraw` 0.18.1 的元素类型）。学习元数据放在 `customData.learn`：

```ts
type LearnNode = {
  v: 1;
  self: string;                            // 元素自己的 id；复制粘贴出的元素 id 不同，宿主不认它的状态
  kind: "concept" | "judgment" | "mission";
  state: "ghost" | "solid" | "anchored";   // 判断节点为 "open" | "closed"
  noteId?: string;                         // 存原话的笔记
  step?: number;                           // 在间隔阶梯中的位置
  dueAt?: number;                          // 下次回访；判断节点为回看日期
  sources?: Array<{ path: string; page?: number; lines?: [number, number] }
                | { url: string; accessedAt: string }>;
  unsourced?: true;
  history: Array<{
    at: number;
    type: "said" | "drew" | "prior" | "did" | "recall" | "reality";
    verdict?: "right" | "partly" | "wrong" | "solid" | "shaky" | "gone";
    sessionId: string;
    from?: { state: "ghost" | "solid" | "anchored"; step?: number };  // 回访：回访前的位置，学习者改判时从这里重算
  }>;
};
```

**连线。** 绑定到两个节点的箭头，标签是学习者的说法（不超过 14 个汉字或 28 个字母，且必须是学习者原话里的片段）。`customData.learn = { v: 1, self, kind: "edge", by: "learner" | "proposed" }`。agent 提议的连线为虚线，学习者确认后变实；学习者用自己的话重新表述同一条连线时，新连线替换提议。节点另带 Excalidraw 自己的 `link` 字段指向它的笔记，所以节点角上的链接图标可以直接打开笔记。

**样式由状态推导，宿主每次写入时重新计算：**

| 状态 | 样式 |
| --- | --- |
| 虚线（没学） | 圆角矩形，`strokeStyle: dashed`，`strokeWidth: 1` |
| 实线（讲出来过） | `strokeStyle: solid`，`strokeWidth: 2` |
| 加粗 | `strokeWidth: 4` |
| 到期 | `opacity: 45`，回访后恢复 100 |
| 判断节点 | 菱形；未回看为实线，已回看加粗 |

**笔记。** 每个实线节点一条 Loci 笔记，ID 为 `learn-<canvasId>-<elementId>`，标题为节点名，标签为主题名和 `learn`，`sourceCwd` 为项目。正文由宿主按段追加：原话及日期、出处、agent 的纠正（标明是 agent 写的）、回访记录。

**资料。** 项目文件夹里的文件，约定放在 `sources/`。不做登记表，agent 自己列目录。

**会话。** `Block` 新增 `learn?: boolean`，与现有的 `loci?: boolean`（`src/features/sessions/model/session.ts:285`）同理：标记激活 `/learn` 的那一轮，之后同一会话的每一轮都有学习权限。

### `loci_learn` 的工具

五个工具。读取不需要批准；写入在计划 turn 被拒绝，其余模式（包括 Supervised）不询问。

| 工具 | 输入 | 宿主做什么 |
| --- | --- | --- |
| `map_read` | `nodeId?`、`stats?` | 返回语义视图：mission、节点（ID、名称、类型、状态、是否到期）、连线（与到期或正在回访的节点相连的连线不带措辞）、学习者手绘但未认领的形状和箭头、最多 3 个待回访节点、未探索节点数。带 `nodeId` 返回该节点的历史和笔记；节点到期或正在回访时笔记不返回（回访结束才给）。`stats:true` 另给统计。不返回 Excalidraw 原始 JSON |
| `map_init` | `subject`、`why`（学习者原话）、`success?`（原话数组） | 没有学习图时创建、打上 `learn-map` 标签并显示在会话旁；把 mission 写在图顶部。已有时不改动 |
| `map_sketch` | `near?`、`nodes`（每次最多 3 个名称）、`edges?` | 在锚点附近添加虚线节点和提议的连线；虚线节点总数超过 9 个时拒绝并说明原因 |
| `map_record` | `nodes[]`、`edges[]`。节点：`kind`（concept 或 judgment）、`id` 或 `label`、`near?`、`evidence`（said、prior、drew、did）、`quote`、`verdict`、`sources?`、`correction?`；判断另有 `wrongIf`、`lookBackAt`；did 另有 `detail` | 核对引用、出处和连线措辞；更新状态、样式和到期时间；创建或追加节点笔记；画出或确认连线；认领手绘形状；一次最多 12 个节点，定向时可一次记录学习者已有的全部知识 |
| `revisit` | `phase`（start、finish、cancel）、`nodeId`；finish 另有 `quote`、`verdict`（solid、shaky、gone），判断的 finish 可带 `principle` | start：遮住学习图，返回要问的节点（判断节点返回当时的全文）。finish：核对引用来自 start 之后，更新阶梯和状态，取消遮挡，返回旧原话供对照；学习者回访期间掀开过地图，solid 降为 shaky。cancel：什么都不改 |

### 不变量落在哪里

| 不变量 | 落点 |
| --- | --- |
| 实线只来自学习者 | `map_record` 的引用校验：归一化空白和全半角后，`quote` 必须是调用会话中用户消息的连续片段，且不在引用行内。实现为纯函数 `src/features/learn/model/quote.ts` |
| agent 只画少量虚线 | `map_sketch` 的上限。`handleCanvasBridge` 的 `checkpoint.save`、`elements.update`（`src/features/canvas/checkpoints.ts:71, 116`）和 `/operator` 的 `canvas.write-data`、`canvas.delete`（`src/features/agent-app/model/agentApp.ts:486, 502`）遇到带 `learn-map` 标签的画布时拒绝，并提示改用 `loci_learn` 或另画一张讲解图 |
| agent 不重排 | `loci_learn` 没有接受坐标的参数。放置由 `src/features/learn/model/placement.ts` 完成，只为新元素找位置 |
| 回访不泄题 | `map_read` 不返回到期节点的原话；`revisit` 记录开始时间，结束时只认开始之后的用户消息 |
| 带出处 | `map_record` 核对路径在项目内存在；否则写入 `unsourced` |

| 文件面板 | PDF 从外部请求跳到指定页；纯文本滚动到指定行；Markdown 的预览没有行号，指定行的链接会切到源码模式并选中这些行。请求"用完即清"，之后正常打开同一文件不会被旧请求拉走 |
| 对话记录 | 学习工具的调用按"读取学习图""记录到学习图""回访节点"命名，阶段标题和图标与画布工具一致；Claude Code 先查找延迟工具的那一行归入学习工具的使用 |
| Settings → MCP 的 Built-in 区域 | 增加 `loci_learn` 一行。它没有开关：只在输入过 `/learn` 的会话里挂上，所以只显示是否可用（缺少 Node.js 时说明原因） |
| 从节点开会话 | 选中虚线节点点"探索"，或到期节点点"回访"，在地图右侧开一个新会话，标题是节点名。provider 和模型沿用该项目上一次的学习会话；应用重启后内存里没有它，就用项目历史里最近一个未归档、非草稿、能学习且已安装的会话，都没有才用第一个可用的 provider（`learnSeed.ts`） |

### 需要先确认的技术前提

阶段 1 的第一步用测试确认下面四点，任何一点不成立都要回到设计。结果见"实现与验证记录"。

1. Excalidraw 0.18.1 的 `restore`、`convertToExcalidrawElements` 和常规编辑会保留 `customData`。复制粘贴是否原样复制它没有依赖：设计里节点状态带 `self`，复制出的元素 id 不同，宿主不认它的状态。
2. 在已有会话中追加第二个内置 MCP 后，Claude Code 和 Codex 都能恢复原对话。画布开关已验证过同类重启。
3. 模型能逐字引用用户的原话。引用校验的失败率要实测；失败率高时放宽归一化规则，不取消校验。
4. Codex 对新服务的工具同样能用 `approval_mode` 把批准交给 Loci。

## 开发计划

规模是我的估计：小指半天以内，中指一到两天，大指三天以上。

### 阶段 0：纯 skill 原型（已取消）

原计划先写一个不改宿主的文件 skill，在两个主题上试用一周，再决定宿主怎么做。2026-10-08 用户决定跳过这一步，直接实现第一版，并要求 `/learn` 内置。当天写在 `~/.agents/skills/learn/SKILL.md` 的原型提示词不再使用，其中的教学规则改写后成为内置 `/learn` 的说明文字。

原型本来要回答的问题仍然有效，改为在第一版的实际使用中观察，答案决定后续调整：

1. 落图这一步像巩固还是像作业？有没有跳过？
2. 宿主摆放节点的位置能不能接受？是否总要自己重排？
3. 每次开头 3 个回访是受欢迎还是想躲？
4. 投资里的判断节点和回看是否自然？"不替你判断"的边界是否可行？
5. 图到 30 到 50 个节点时还看得清吗？

## 风险

| 风险 | 应对 |
| --- | --- |
| Excalidraw 没有自动布局和折叠，节点多了难用 | 宿主只为新节点找位置，学习者自己整理。阶段 0 的问题 5 给出实际上限，超过后做子画布 |
| agent 判断"讲对没有"不完全可靠 | 存原话和出处供核对；学习者可以改判；真正的校准靠隔时回访 |
| 引用校验过严，模型改了一个标点就失败 | 归一化空白和全半角；失败时返回明确的错误；实测失败率 |
| 落图被当成作业跳过 | 后果只是节点保持虚线，不惩罚。阶段 0 的问题 1 专门观察 |
| 模型质量差异大 | 状态、放置、到期都在宿主，换模型不影响。讲解质量无法保证 |
| 投资领域编造内容或被当成建议 | 讲解必须带出处；时效性数字不进概念节点；提示词禁止买卖建议。最后一条只靠提示词，没有宿主保证 |
| 需要本机有 Node.js 20.11 以上或 Bun | 与现有画布 MCP 相同的限制 |

## 已定的四个选择

用户于 2026-10-08 确认：

1. **学习工具在 Supervised 模式下不询问。** 每次写入范围窄、有证据校验、可在面板撤销。这与现有画布工具在 Supervised 下会询问不一致，是有意为之。
2. **每个实线节点一条笔记。** 可以被搜索、被 `@` 引用、被学习者扩写。代价是笔记列表里条目变多。
3. **起始数字：虚线上限 9、回访上限 3、阶梯 1/3/7/21/60/150 天。** 阶段 0 之后按实际感受调整。
4. **从节点开的新会话沿用该项目上一次学习会话的模型选择。**

### 没有验证的

- macOS 和 Windows；打包后的应用能否找到 `resources/learn-mcp`（只有"清单里登记了、文件存在"的测试）；Bun 运行时。
- 多窗口；计划模式的实机行为（只有自动测试）；Claude 的 Opus 和 Sonnet、其他 provider 的表现。
- 回访时隐藏连线措辞（V5 的后半）是在实机验证之后才发现并补上的漏洞：此前完整的 `map_read` 会把与到期节点相连的连线标签原样给 agent。这一条只有自动测试，没有再做实机回访。
- "不替学习者判断"和"讲解带出处"只靠说明文字，宿主不保证：只在 Claude Code 的 Haiku 5.5 上试了一次投资判断，它守住了；换一个模型、换一种问法都可能不同。
- 真实的时间流逝：到期用数据库里改日期模拟（状态注入），1 天以后的几级间隔只靠单元测试，没有真的等。
- 地图超过约 10 个节点后的可读性；节点摆放在更大地图上的表现；回访遮挡层在地图面板未打开时的表现；撤销历史里"静默写入"的实际效果。
- 最关键的问题没法靠这类验证回答：学得是否更牢、是否愿意坚持。阶段 0 里列的五个问题（落图像巩固还是像作业、摆放位置能否接受、每次三个回访是否想躲、判断节点是否自然、地图变大后是否还看得清）需要真实使用来答。

### 与设计的差异和已知缺口

- 引用校验归一化后只比较字母和数字（忽略空白、标点、大小写、全半角），不是严格的逐字符。
- `loci://file/` 链接相对窗口里当前打开的项目解析；从另一个项目的笔记里点，会指到错的位置。
- 教学规则的完整文字只在输入 `/learn` 的那一轮发给 agent；换 provider 或上下文被压缩后，agent 仍有工具说明和 `map_read` 返回的 `rules`，但没有完整文字。
- "做过"的证据是 agent 自己的陈述：宿主要求节点已被学习者解释过，并在检查器历史里注明"agent's statement"，但它仍能让节点加粗。
- Markdown 文件在点过带行号的链接后会一直停在源码模式，直到手动切回预览。
- 实机里模型偶尔的小问题：把 `loci://canvas/…` 当纯文本打出而不是 Markdown 链接；一次调用里对同一节点记两条（宿主已能处理）；把"实线"说成"已掌握"（工具说明和规则里已写明"实线只表示讲过，不等于掌握"）。
- 阶段 3 的候选项没有动。
