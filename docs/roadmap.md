# Loci Roadmap

> 更新于 2026-11-11（v0.10 规划）。这份路线图公开维护（build in public），按版本推进，每个版本完成后再细化下一个。

## 定位

**Loci 是给工程师的 AI native 学习工作台：一位常驻的导师，为你写课、讲透原理，每个论断都能一键回到一手材料。**

- **一个导师，一个主题。** 每个导师是一个长期存在的 agent：有自己的 Soul（长期指令）、记忆、资料库、课程和工作目录。
- **导师写课，一手材料作证据。** 课文是导师按你的基础写的讲解：问题、机制、图、例子、取舍。官方文档、规范、论文和源码由导师采集，作为每个论断的出处，点一下就能看原文；想深入时再读原文。
- **真 agent，能动手。** 导师背后是你本机已登录的 agent CLI（Claude Code、Codex、Grok、Antigravity 等），能 clone 仓库、跑代码、做实验，不需要另配 API key。
- **本地优先。** 数据留在本机，没有账号服务，没有统计。从 v0.7 起，其他设备可以远程连到这台主机；数据仍只存在主机上，客户端只缓存看过的内容。

### 学习循环

```
目标 → 全景图 + 路径 → 读导师写的课 → 在课上提问 → 课文随提问修订 → 用得上
       （导师采集出处）  （出处一键可查）  （问答留在课上）             （面试怎么讲 / 对照手头的系统）
```

效率来自消掉五种摩擦：找资料、读不懂原文、每次重新交代上下文、中断后难以重新开始、读完不等于懂。

### 不做什么

- 不做掌握度考核门槛、答题证据判定和间隔复习排期。读到底就算读完；想检验时由你自己说"考我"。
- 应用里不写爬虫。抓取是导师（agent）的能力，Loci 提供存储、阅读和课程这些底层原语。
- 不把 Loci 做成通用的 agent CLI 外壳。和学习无关的功能会被删掉；但各家 agent CLI 的适配都保留，导师可以跑在任意一家上。

## v0.3（已发布，2026-11-01）：导师质量 + 和导师一起阅读

- **导师默认 Full access**，设置里可以按导师或全局改回其他模式。
- **Loci CLI**：应用的全部能力都能从命令行完成（导师、课程、资料与导读、笔记、画布、文件、高亮、阅读区、会话、设置），用于端到端测试，也让外部 agent 扮演导师。UI 与 CLI 共用一套命令层。
- **左栏重做**：顶部图标分段（选中的展开成带名字的胶囊），课程分段是一行课程切换与进度加一份像目录一样的大纲；各栏表头就是窗口顶栏，不再有单独的标题栏与面包屑。
- **和导师一起阅读**：所有阅读器都能高亮、批注、选中即问；导师知道你读到哪一段；回复里的引用能跳到原文并闪一下。正文排版 15/26、限定行宽，可选衬线阅读字体；代码有语法高亮和行号。
- **导师质量**：评估工具（`npm run eval`，导师与评分都跑在 grok 上）；一手资料与导师导读分开；Mentor 与 Lens 模板按评估结果重写；应用内更新提示。
- 一轮 UI 评审（5 个区域、72 项）与 unslop 视觉打磨。

## v0.4（进行中）：读码 + 存储底座，用沙箱课题验收

**验收方式：** 在 v0.4 上从零做一位新的沙箱导师，课题是 CubeSandbox、Perplexity SPACE、E2B runtime 三个开源仓库（`~/Loci/repos/`）。旧的沙箱导师（0.1 时期的内容：61 课全是导师自写课文、没有一手资料、仓库不在工作目录）已存档到 `~/Loci-archive/sandbox-mentor-v0.1/`，留作对照。

验收标准：

- 一句话说明目标后，**5 分钟内**开始读第一份一手资料。
- 至少 **10 份一手资料**，原文、钉住版本或 commit：virtio 规范、KVM API 与内核文档、三个仓库的 README 与设计文档、相关论文。
- 一条由 **3–5 门短课** 组成的学习路径，每门至少一课**代码导览**、至少一课**三方对比**。
- 评估工具加入沙箱课题，自动检查与评分达标。
- 用户用它连续学一周，不需要离开 Loci。

### 1. 存储底座：一个导师 = 一个文件夹

```
~/Loci/<导师>/
├─ mentor.json            身份：名字、头像、provider、模型、权限
├─ SOUL.md · memory/      长期指令与记忆
├─ sources/<id>.md        一手资料原文，front-matter 记 sourceUrl / version / fetchedAt
├─ guides/<id>.md         导师写的导读与简报
├─ courses/<id>.yaml      课程结构（课 → 资料#章节 或 repos/…#L）
├─ notes/<id>.md · canvases/<id>.excalidraw
└─ repos/<owner>/<repo>   源码
```

- 内容（资料、导读、课程、笔记、画布）以文件为准；SQLite 只放高频变化的状态与索引：对话、阅读进度、高亮批注、阅读位置、全文搜索。
- 导师名册离开 WebView 的 localStorage。
- 文件改动（导师或你自己改的）实时反映到应用里。
- 从 0.3 的数据自动迁移，不丢数据；导出 / 导入一位导师 = 打包 / 解包它的文件夹。

### 2. 读码

- 代码导览课是一等课型，钉住 commit：`repos/<repo>@<sha>:path#L12-40`；仓库 HEAD 变化时提示课文可能过期。
- 代码阅读器：符号大纲、仓库内跳转到定义、查找引用。轻量实现（tree-sitter / ctags），不引入 LSP。
- 沿用 v0.3 的高亮、批注、选中即问。

### 3. 对比课

- 一课可以指向多个仓库里的同一个机制（例如三个项目的快照 / 恢复）；阅读区把几段原文上下排在同一页，仍然只有一个阅读区。

### 4. 学习路径

- 一位导师可以有一串短课（每门 6–12 课），有顺序和前置；课程分段显示整条路径与各门进度。

### 5. PDF 作为一手资料

- 论文等 PDF 可以带来源地址入库，页作为章节，引用 `#p7`。

### 6. 长回合可见进度

- 导师采集资料、写课程的长回合里，实时显示它在做什么：正在保存哪份资料、写到哪一课。

### 7. 沙箱导师 v2 验收

- 按上面的验收标准做；评估工具加入沙箱场景。

### 推进顺序

1. 存储底座（1）。
2. 读码（2）与学习路径（4）。
3. 对比课（3）、PDF（5）、长回合进度（6）。
4. 沙箱导师 v2 验收（7）。

## v0.6（规划中）：阅读体验 + 减法

来自 v0.5 一天真实使用的反馈。

### 阶段一：修与减

- **PDF 选中**：补上 pdf.js 的 `endOfContent` 与拖选时的 `selecting` 状态（CSS 已有、JS 没接），选区不再在行间、栏间乱跳；首尾吸附到整词。
- **阅读位置持久化**：每位导师、每个页面记住读到哪（PDF 页码与页内位置、Markdown 段落、代码行），存进 `mentor_state`，切走再回来时恢复。
- **删除导师 = 真删**：导师文件夹移到系统废纸篓（可找回）；数据库里它的对话、高亮批注、课程进度、阅读位置、译文、视图状态一并清掉。确认框写清楚删什么。共享的 `~/Loci/repos` 不动。
- **移除画布**：代码、UI、CLI `canvas.*`、Canvas MCP、`@ 画布`、数据表与 Excalidraw 依赖全部删除；已有的 `.excalidraw` 文件一并清理。

### 阶段二：高亮与批注重做

- **样式**：单色纸墨的高亮（浅底或下划线，无描边）；大卡片换成贴着选区的工具条：高亮 · 问导师 · 存到笔记 · 复制引用。批注默认收起。
- **问导师**：不再弹卡片，把引用放进右侧输入框作为引用块，接着打字即可。
- **按块高亮**：Markdown 的表格、Mermaid 图、代码块、图片可以整块高亮和提问，导师收到整块源文本；PDF 用框选区域处理图与表（截图 + 区域内文字）。
- **存到笔记**：高亮和批注存成你自己笔记里的引用块，带原文链接，点击跳回原文。每次存时选目标笔记（也可新建），默认选中上次存的那篇。

### 阶段三：上下文与导师

- **“正在读”可见**：`<reading_now>` 本来每轮都会带给导师；输入框上方显示一个标签（资料 · 页码 · 选中行数），可以在单轮里去掉。
- **@ 分组**：课程 / 资料 / 导读 / 笔记 / 高亮 / 文件；空查询先显示最近打开和当前课程；支持 `@资料/` 这类前缀过滤。
- **Lens 默认速读**：clone 后只写一页简报（是什么、核心原理、一条关键数据流、三个值得读的文件），不建课程；简报末尾“深入读 → 建课程”，或你明确要深入时才走建课流程。暂不新增模板。

## v0.7（开发中）：远程访问

在笔记本上建的导师和课程，回家后在 Mac mini 上接着学。不做同步：数据、agent CLI 和模型配置只留在主机（笔记本）上，其他设备装同一个 Loci，经隧道连到主机，像 Claude Code / Codex 的 remote control。远程端和本机同级：对话、阅读、笔记、PDF 高亮、设置、导师权限（包括 Full access）都能用、都能改。远程访问默认关闭，不开就和现在一样。设计见 [remote-access.md](remote-access.md)，实现细节见 [architecture.md](architecture.md#remote-access)。

状态：阶段一至四已实现，正在做发布前的验收。两台 Mac 经 Cloudflare Worker 的实机验收还没走。

### 阶段一：传输抽象（已完成）

- **命令清单**：194 个已注册命令各归一类：读、写、会话动作、在主机执行、客户端本地、永不对外。远程白名单由这份清单生成，有测试保证没有漏项；`harness_*`、控制通道、工作区重置永不对外。
- **Transport**：直接 import `@tauri-apps` 的地方全部收进 `src/platform`；接口是 `call` / `listen` / `fileUrl`，字节读写走命令，没有单独的 blob 接口；本机 `TauriTransport` 和远程 `RemoteTransport` 两个实现。
- **摸清会话状态流**：接缝是 `useSessionRuntime` 的 `updateSessions`；会话和块都不可变，按引用比较就能产出增量。

### 阶段二：主机与会话主控（已完成）

- **Gateway**（Rust）：一条连接上跑 `call`/`result`、`subscribe`/`event`、blob 分块和上传帧；按清单转发，会话动作和意图交给主窗口。
- **会话主控**：主机窗口是会话唯一的驱动者；本机 UI 和远程设备用同一张意图表；快照和增量带 `{epoch, seq}`，主机留 8 MiB 的 patch，断线按序号补齐，补不上时取快照。
- **LoopbackTunnel**：本机两个窗口走同一条加密通道和 Gateway，作为开发和测试的主循环。

### 阶段三：隧道与身份（已完成）

- **Tunnel 抽象** + `AlmaRelayTunnel`：基于 [alma-relay](https://github.com/yetone/alma-relay)，部署在自己的 Cloudflare Worker 上；主机主动外连，不需要端口转发。协议 2，旧 relay 回退到 1。
- **端到端加密**：X25519 握手 + AES-256-GCM，不管走哪条隧道都开着；relay 只看到密文和路由令牌。
- **设备组**（身份抽象的第一个实现）：在设置里显式创建设备组，新设备用组密钥加入，无需批准。加入后主机在下一次名单刷新时接受它，第一次连接可能被拒，约 3 秒后自动重试。在任意设备上可以看到全部设备、在线状态，并移除某台。没有“新设备加入”的全组通知，新设备在列表刷新时出现。设备列表放在独立的 Worker（`services/device-registry`）的 Durable Object 里，设备记录由组密钥签名，心跳由设备密钥签名。

### 阶段四：客户端体验（已完成）

- **连接到设备**：在设备列表里点“连接”，打开一个客户端窗口；顶部状态栏显示主机名和连接状态。
- **主机文件**：文件选择器换成主机文件浏览器；拖入、粘贴的文件和图片先上传到主机。
- **PDF 与图片**：经 blob 通道读取，阅读、选中、高亮和本机一致。
- **缓存**：缓存看过的导师、课程、文档、PDF、笔记和对话；主机离线时只读，写操作和发消息禁用，不排队写入。
- **主机不睡**：开启远程访问且接电源时阻止系统空闲睡眠，设置页写明这一点。合盖或用电池时的睡眠挡不住。

### 与规划不同的地方

- **设置推送借用了会话 feed。** 主机共享的设置作为 `settings` 消息，和快照、patch 共用 `{epoch, seq}`；客户端改设置走 `settings.set` 意图。没有另开一条设置通道。
- **连接码由组密钥派生。** 每台主机的连接码 = HKDF(组密钥, 主机 deviceId)，成员各自算出，注册表和 relay 都不知道组密钥，也不需要分发或存储连接码。
- **移除设备是永久的。** 注册表留下签名墓碑，同一个 `deviceId` 之后不能再加入；被移除的设备要先“退出设备组”换一把新设备密钥，才能用组密钥回来。
- **轮换组密钥等于换一个组。** `groupId` 就是组公钥，换密钥后旧组成员连不到新组，必须全部重新加入；设计稿里“只影响以后的加入”不成立。
- **客户端只需要注册表地址**（和可选的注册表密钥）。relay 地址由主机心跳里的 route 带回，relay 注册密钥只在客户端也要当主机时才需要填。
- **设备列表是独立 Worker。** 它和 relay 部署在同一个 Cloudflare 账号下，但不是 relay 的附加路由。
- **客户端缓存断线时保留。** 每台主机 256 MiB，离线时要靠它读；移除设备或退出设备组时才清。
- **事件扇出只有会话 feed**（含共享设置）。主机发给本机窗口的其他事件不转发给客户端。

### 验收

本机 loopback、本地 relay 和本地注册表上的集成测试已跑通：两端握手、断线补齐、上传、设备加入与移除、移除后被拒。两台 Mac 经 Cloudflare Worker 的实机验收还没做：在 Mac mini 上连到笔记本，把一节课从读、到问导师、到高亮和记笔记完整走一遍；同时在笔记本上打开同一位导师，两边看到同一段对话。

### 不做

- iPad 端（见“之后的版本”）。
- `TailscaleTunnel` 和 Tailnet 身份：抽象留好，实现放到之后。
- 把会话驱动下沉到 Rust 做无头主机。

## v0.10（已发布，2026-11-12）：讲得懂

来自 v0.9 一周真实使用（K8s、网络、沙箱三位导师）的结论：一手资料直接当课文读不动。一课只是指向原文某一节的指针，没有任何导师的文字，提示词又要求导师“不先讲、被问才讲”，结果每一课都要先问一句“怎么理解这一节”，原文基本没读，讲解散在对话里，事后再手动存笔记。三位导师一共只留下 8 条高亮；K8s 导师一晚写了 4 门 47 课和 20 个实验脚本，读了 8 课，实验一个没跑。

这一版把一手资料从“课文”降为“证据”，和 v0.9.1 的“代码是证据”是同一条原则。不回到 v0.1 那种没有出处的自写课文：每个论断都要能点回原文。

### 1. 会说话的课

- **课文由导师写。** 一课是一篇 5–10 分钟的讲解：它回答什么问题、机制、一张图、一个走到底的例子、取舍或失效方式、两三行收尾。原文作为出处引用在课文里，点一下打开到那一段；后退回到课文。
- **课程模型**：课有自己的正文（导师文件夹里的 Markdown 文件）；原来的“指向资料 / 文件 / 对比”保留为这一课的出处。只有标题、还没写的课显示为 *planned*。
- **模板重写**：Mentor 与 Lens 去掉“不先讲”；先全景后细节；术语先解释再用，缺的前置知识就地补或单开一课；每个机制一张图加一个例子；实验只在你要求时准备。
- **评测**：新增“独立可读”一项，由带着设定背景的模拟学习者读课文，列出读不懂的术语和跳步；去掉对导师自写文字的扣分。

### 2. 先全局，后细节

- 每门课的第一课是全景图：问题、几个部件和它们的关系、每一章往图上加什么。
- 路径先只有标题；导师一次只写一章（3–4 课），你读到这一章倒数第二课时再写下一章，按你问过什么、在哪里慢下来调整。

### 3. 问答留在课上

- 在某一课里发出的提问记在这一课上：课末列出“在这课问过的”，点一下回到那段对话。
- 导师答完后修订课文，让这个问题不必再问；被问过不止一次的，写进课文显眼处。
- 课末有下一课的入口。

### 4. 用得上

- 导师知道你为什么学（面试、工作里的决定、手头的系统）。需要你讲清或辩护的机制，课末带一段“怎么讲”：真实的问法、一分钟的回答、区分理解与背诵的追问；每门课最后一课把这些汇总。不强求每课都有。

### 5. 回来就能接上

- 隔了一段时间再打开导师时，一眼看到上次读到哪一课、上次问的是什么、下一课是什么；导师每轮也知道你离开了多久。

### 6. 修与减

- **已读判定**：打开 8 秒不再算读完；PDF 与外部文件课不再一点开就算读完。
- **⌘K 搜正文**：资料、导读、课文和笔记的全文，而不只是标题。
- **删除**：habits（引擎、CLI 与孤儿界面）；build-your-own 课型；MCP 与 Skills 设置页及输入框里的选择器；导师设置里的“Other folders”；按项目的通知设置；四张死表与无人引用的模块。
- **自用数据重来**：旧的五位导师导出存档后删除，在 v0.10 上从零建导师验收。

### 不做

- 考核门槛、复习排期照旧不做。
- 实验（`lab/`）不再由导师主动准备；阅读区的终端视图继续放在之后的版本。

### 推进顺序

1. 修与减（6）。
2. 会说话的课（1）与先全局后细节（2）。
3. 问答留在课上（3）、回来就能接上（5）；“用得上”（4）只在提示词里。

## v0.11（已发布，2026-11-12）：像一本书，不像一个聊天窗口

v0.10 让课文成了主角，但外壳还是 agent CLI 的三栏：目录、内容、对话各占一栏，对话永远在场。这一版让布局跟上：读的时候是一本为你写的书，导师在页边。

### 1. 一位导师，一份目录

- 去掉“学习路径 → 短课 → 章 → 课”四层。一位导师只有一份目录：**章 → 课**。原来的短课就是章。
- 删除学习路径（`_path.yaml`、`path.*`）、课程切换菜单和 “Other courses”。存储上一位导师仍可有多门课（Lens 每个仓库一门），它们在同一份目录里依次排开。
- 导师仍然一次只写一章；后面的章只有标题。

### 2. 知识树代替等高线图

- 没有打开任何页面时，阅读区是一棵自下而上的墨线树：树根下是几圈等高线，地基那一章是最低的一枝，越往上越晚学；每章一根枝，每课一片叶，立在同一章上的两章从同一高度分叉，最后一章是树冠。章的依赖由导师写在课程里。
- 只画真实的东西：读过的是墨叶，在读的是灰叶，写好没读的是浅叶，planned 是虚线；接下来读的那一课带一圈圈叶脉。树干和枝的墨色随读到哪里往上长。点叶子打开那一课。
- 多门课时每门一棵树，并排。

### 3. 首页与引导

- **没有导师时**：整个窗口是一页开始页，一个输入框写“想学什么、为了什么、已经会什么”，下面两三个例子可以直接点。回车就建好导师并开始写第一章。本机没有可用的 agent CLI 时，在这一页说明要装什么、怎么登录。
- **有导师时**：开始页是左栏顶部的入口，用来建下一位导师；v0.10 的回来卡片保留。
- **第一章写出来之前**：阅读区显示导师正在做什么（找到了哪些出处、在写哪一课），而不是空白。
- 不做分步导览。选中即问、出处切换各在第一次用得上的地方提示一次。

### 4. 读为主，导师在页边

- 打开一课时，课文居中、放宽；目录收成左侧一条窄栏，悬停或按键展开。
- **页边问答**：选中一段提问，回答出现在这段旁边的页边，并留在那里；下次读到这里还在。课末的“在这课问过的”改为页边的这些条目。
- 完整对话仍是右侧一栏，但读课时默认收起，一个按键打开；没有打开课时照常展开。
- 课文底部有一个输入框，问的是这一课。

### 5. 术语表

- 导师为每个导师维护一份术语表：术语、一句话定义、在哪一课讲的。
- 课文里出现的术语有虚线下划线，悬停看定义，点击去那一课。还没讲到就用了的术语，导师写课时自己能查出来。

### 6. 课文修订看得见

- 导师因为你的提问改了课文后，这一课标出“改过”，可以看改了哪几处。

### 7. v0.10 遗留

- 课末两块与正文栏对齐；远程窗口里点问题能跳到对话；删除 Skills 的后端；用真实模型跑一次评测，拿到“独立可读”的基线。

### 推进顺序

1. 目录扁平化（1）与遗留（7）。
2. 开始页与引导（3）、知识树（2）。
3. 读为主的布局与页边问答（4）。
4. 术语表（5）、修订可见（6）。

## 之后的版本

### 实验（原 M4）

- 导师在工作目录的 `lab/` 里准备练习；阅读区可以切成终端或文件视图，你自己跑，或者导师带你跑。
- 沙箱课题的 KVM / microVM 实验在 Apple Silicon 上跑不了，需要远程 Linux 主机或本机 Linux 虚拟机。

### 沉淀（原 M5）

- "讲给导师听"的费曼模式。
- 课程与资料可以打包分享（v0.4 的文件夹存储打好了基础）。

### 远程访问的后续

- **iPad 客户端**：客户端只是 v0.7 的“连接到设备”模式，不需要重写。优先用 Tauri 2 的 iOS 构建打包同一份前端，只保留客户端模式（iPad 上不跑 agent CLI）；代码随 App 安装，不经 relay 下发，端到端加密才可信。要做的是适配：三栏在 iPad 宽度下折叠、触屏选中文字提问和高亮、键盘快捷键、锁屏后的通知。
- **Tailscale**：`TailscaleTunnel` + Tailnet 身份，换隧道不改上层。
- **无头主机**：会话驱动从前端下沉到 Rust，主机不再依赖窗口。

### 换掉 Tauri（暂缓）

研究过用 [Native Shell](https://github.com/longbridge/nsh) 替换 Tauri，得到原生的 iPhone / iPad 端。框架还太新，等它成熟再推进，见 [native-shell.md](native-shell.md)。

### 以后再说

首次启动引导、habit 与导师主动跟进、Today 首页、学习者画像。现有的 habit 代码保留，但不再投入。
